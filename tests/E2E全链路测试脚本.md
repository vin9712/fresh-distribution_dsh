# E2E 全链路手工测试脚本（订单 → 送货 → 验收 → 退货）

> **版本**：v1.0（2026-08-28，配套 s14 订单-送货-验收链路重构 T1~T8）
> **环境**：本地 `./dev.sh start` → 访问 **http://localhost:1025**（admin 登录）
> **配套**：只读冒烟 `node tests/e2e-smoke.mjs`（巡页防 404/5xx）；本脚本是**含业务写入**的全链路
> **约定**：每步给出「操作路径 → ✅预期」。建议按顺序走完，耗时约 30~40 分钟。
> ⚠️ 本地后端连的是**远程测试库**（39.96.76.240）。测试数据统一用「**E2E**」前缀命名，走完 T13 清理，不要在真实客户上录测试单。

---

## T0 环境自检（1 分钟）

1. `./dev.sh status` 显示前后端运行中；`node tests/e2e-smoke.mjs` 输出 **PASS**
   ✅ 五个关键页面无 404/5xx
2. ⚠️ 若改过后端代码：必须先 `./dev.sh build` 再 `./dev.sh restart`，否则跑的是 ~/.m2 里的旧 jar（新接口 404）

## T1 测试数据准备（约 10 分钟，一次性）

推荐新建独立测试客户（不污染真实客户）：

1. **基础信息 → 客户信息 → 新增**：名称「E2E测试客户」，添加 **2 个配送点**（E2E点A、E2E点B）
   - ✅ 保存成功；表单底部「组单策略」默认 **DELIVERY_POINT_DATE（每配送点一单）** + 相同商品合并
2. **基础信息 → 客户商品**：给该客户指派 2~3 个现有 SKU（如 土豆、白菜），配送点选「通用」
3. **基础信息 → 商品报价**：新建报价单（当日生效），给上述 SKU 填执行价并**发布**
   - 其中一个 SKU 准备**两档价**（后面 T2 用两个配送点价不同验证不同价拆行 D-024）——若配送点报价可用则配 E2E点A/点B 不同价；否则在两张订单里手工改价（录单改价有橙色提醒，属预期）

> 💡 复用现有客户也可，但测试订单会挂在真实客户名下，收尾务必走 T13。

## T2 录单（2 张订单）

路径：**单据管理 → 销售订单 → +新增明细**

订单①（E2E点A）：
1. 选送货单位=E2E点A、配送日期=**明天**
2. 加行：土豆×10（默认价）、白菜×5
3. 把土豆单价**改小 0.5 元**（有改价提醒，确认保存）
4. 保存 → 订单状态=**制单**

订单②（E2E点B，同日期同客户）：
1. 加行：土豆×8（**用另一档价**，与订单①的土豆最终价不同）、白菜×5
2. 保存

✅ 检查点：
- 两单同客户同配送日期、不同配送点
- 订单①内土豆改价成功（录单快照价原则）

## T3 出单与幂等（统一生成服务）

1. 在**订单②的录单页**点底部 **「本客户订单已录完 · 出送货单」** → 确认弹窗（提示幂等/作废重建/补充单规则）
   ✅ 成功消息含**新送货单号**；未跳过（两单都是遗漏）
2. 重复再点一次
   ✅ **幂等跳过**，无重复单据（D-021）
3. **单据管理 → 送货单据** 查看今天生成的单
   ✅ 当前策略=每点一单 → 生成 **2 张**送货单（E2E点A、E2E点B 各一张），状态=待打印
4. 每张单点 **「来源明细」**
   ✅ 各商品行显示来源订单号/分配量；土豆按**两档价拆成两行**（D-024 不同价必拆行）
5. 订单列表两单：
   ✅ 状态=审核、显示**送货单号**列有值、「可撤回」标识出现

## T4 补单（作废重建分支，D-022）

1. 回录单页，补录**订单③**（E2E点A，同日期，加一行白菜×3），保存并**确认**
2. 再点「本客户订单已录完 · 出送货单」（或订单列表勾选 → 生成送货单）
   ✅ E2E点A 那张**未打印**的旧单被**作废**（状态=已作废，tag 悬浮显示原因「补单重建」），生成**新单号**覆盖该客户当日**全部**已确认订单（①②③ 都进新单，不是只拼订单③）
3. 旧单详情：状态=已作废；新单「来源明细」包含三张订单的分配
   ✅ 来源订单仅 ①②③ 被锁定，同客户未进单的其他订单不受影响

## T5 送达（免纸原因，D-018）

1. 送货单页对 E2E点A 的新单点 **「标记送达」**（单据还**未打印**）
   ✅ 弹出**免纸原因必选**弹窗（免纸客户/电子单据/录单补登/设备故障/其他，选「其他」需填说明）
2. 选一个原因确认
   ✅ 单据状态=已送达，备注追加 `[免纸送达:…]`
3. 订单列表：
   ✅ 订单①②③ 状态=**已配送**；出现 **「去验收」** 按钮
4. 护栏：打开订单①尝试编辑明细
   ✅ **拒绝修改**（提示用新增销售订单/退货单，G6 护栏）

## T6 去验收定位（by-order 定位 + 高亮）

1. 订单列表对订单②点 **「去验收」**
   ✅ 自动跳转**验收单页**，定位到该订单所在的验收单（无则引导建草稿），订单②贡献的行**黄色高亮**，顶部有定位提示条
2. 对订单①同样操作
   ✅ 高亮行切换为订单①贡献的行

## T7 验收录入（点级实收 + 双向原因 + 镜像）

在验收单页（承 T6 打开的草稿）：

1. 明细按**商品分组**展示：组头=应送/实收/差异合计（只读），成员=各配送点行
   ✅ A/B/C 类统一；土豆组内可见 E2E点A、E2E点B 两行
2. E2E点A 的土豆实收改 **8**（应送 10，短收 2）
   ✅ 「验收差异」列 **-2 红色**；**短收原因**变为必填（不填直接保存/提交被拦，提示「短收差异必须填写原因：土豆」）
3. E2E点B 的白菜实收改 **6**（应送 5，超收 1）
   ✅ 差异 **+1 橙色**；**超收原因**必填（双向原因 D-013）
4. 把 E2E点B 白菜实收改回 5
   ✅ 差异归零，原因自动**清空**
5. 提交验收
   ✅ 成功；来源订单①②③ 状态=**已验收**
6. 回订单列表打开订单①：
   ✅ 实收两列为**只读镜像**（土豆 8 = 按点级占比同步），不可编辑；订单页无任何实收录入入口（方案A 已下线）

## T8 撤销验收（D-014）

1. 验收单页对该已提交验收单点 **「撤销」**，原因填「E2E 测试撤销」
   ✅ 验收单回**草稿**；订单①②③ 状态回**已配送**；订单页镜像实收被**清空**
2. 撤销按钮消失（仅已提交状态显示）；再**重新提交**验收（沿用 T7 的实收），订单回「已验收」

## T9 退货单全流程（D-032/D-034）

1. **单据管理 → 退货单 → 新建退货单**，选该已提交验收单
   ✅ 明细带**累计已退**；可退上限 = 实收 − 累计已退
2. 白菜退 **2**（实收 5）
   ✅ 单价自动锁定**原验收价**且不可改；金额后端重算
3. 试图把退货数量改成超过上限的值
   ✅ 提交时被拒，提示含**可退量**
4. 保存草稿 → **提交**
   ✅ 状态=已提交(质检中)；提示 settle_scope 快照（来源订单未月结 → 当期冲销）
5. **质检**：逐行选「可再售(入库)」（字典驱动，值 1/2）→ 完成
   ✅ 状态=质检完成，记质检人/时间
6. 再次新建退货单选同一验收单
   ✅ 白菜**累计已退=2**，可退上限变 3（占用口径正确）

## T10 作废与解锁（G4）

1. 对 E2E点B 的送货单（未打印）点 **「作废」**：选原因「录单错误」，勾选**「作废后立即重新生成」**
   ✅ 旧单作废 + 新单生成一气呵成；订单②重新进单
2. 若不勾重新生成：订单②在订单列表的送货单号列变空、**可撤回**标识消失（订单解锁，EXISTS 有效分配口径）

## T11 编辑护栏抽查（G6，其余状态）

| 场景 | 操作 | ✅预期 |
|---|---|---|
| 已配送订单 | T5 后已验过 | 拒改，引导新增销售订单 |
| 已验收订单 | 打开订单① | 拒改 |
| 已分配（CONFIRMED+进单） | 把某新订单确认后再改 | 拒改，提示先作废送货单 |
| 制单/未分配 | 新建草稿 | 正常编辑、撤回、删除 |

## T12 客户日总表（D-027/028）

1. **单据管理 → 客户日总表**：选 E2E测试客户 + 明天的配送日期 → 查询
   ✅ 标准品名 + 配货总量 + 各配送点小计（E2E点A/点B 两列）；**无价格列**；同商品跨订单合并展示
2. 点 **「打印」**
   ✅ 打印样式仅输出总表正文

## T13 清理与收尾

1. 本地停环境随意（`./dev.sh stop`）
2. 测试数据处理（远程测试库）：
   - 测试订单已进单/已配送的：按设计**不物理删**（作废单/历史单保留审计）；确认单据 tag 与备注带「E2E」便于识别
   - 如需彻底清理，联系管理员按 id 精准删除（**禁止**直接 UPDATE 状态绕过状态机）
3. 工作台检查：
   ✅ 待验收卡片指回 /order/acceptance；无「送货单生成异常」红色告警（若出现，点跳转送货单页手工补生成，属定时任务兑底逻辑）
