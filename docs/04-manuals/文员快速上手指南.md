# 文员快速上手指南

> **适用对象**：文员 / 录单员
> **系统入口**：http://localhost:1025（开发环境）
> **配套文档**：完整功能细节见 [操作手册.md](./操作手册.md)，本指南只讲"每天要干什么、怎么干"

---

## 一、文员的职责一句话

**把客户的订单录对，把货验收实，把客户资料和报价维护好。**

日常 80% 的时间花在两个页面：**销售订单** 和 **验收单**；其余是周期性的 **新客录入** 和 **报价维护**。

## 二、文员常用页面地图

| 页面 | 菜单位置 | 用途 | 频率 |
|---|---|---|---|
| 工作台 | 首页 | 看待办：待录订单 / 待采购 / 待打印 / 待验收 / 待处理加退换 | 每天开工先看 |
| 销售订单 | 单据管理 → 订单 | 录单、核明细、改数量单价 | ★★★ 每天 |
| 验收单 | 单据管理 → 验收 | 对照送货单填实收数量、损耗原因 | ★★★ 每天 |
| 送货单据 | 单据管理 → 送货 | 打印送货单、查看配送状态 | ★★ 每天 |
| 客户信息 | 基础信息 → 客户信息 | 新建客户 + 配送点 | ★ 有新客才做 |
| 客户商品 | 基础信息 → 客户商品 | 批量导入客户能订的商品 | ★ 有新客才做 |
| 商品报价 | 基础信息 → 商品报价 | 维护执行价 | ★ 每 1–2 周一轮 |
| 别名与映射 | 基础信息 → 别名与映射 | 临时商品管理、转正 | ★★ 随时清一清 |

> 提示：任何页面按 `Ctrl + K` 可以全局搜索客户 / 商品 / 订单。

## 三、每日工作清单（建议顺序）

### ① 开工：看工作台
打开首页「工作台」，五张卡片就是今天的活：
- **待录/待确认订单** → 去订单页录
- **待生成采购单** → 提醒业务/主管确认
- **待打印送货单** → 去送货页打印
- **待验收** → 去验收页处理
- **待处理加退换** → 核对加退换单

### ② 订单核对
在「销售订单」里逐单检查：
- 左侧明细表：**名称、单位、数量、单价、金额** 是否正确
- 右侧面板用「常用 / 最近」快速挑商品，不用翻全部商品
- 录单时改了价会有提醒，确认是有意为之再保存

### ③ 验收（应收 vs 实收）
核心原则：**下单数量不改，以实际收到为准。**
- 从送货单生成验收单后，进入明细对话框
- 每行有两列：**送货数量（应收）** 保持原样，只填 **实收数量**
- 数量对不上的，顺手选/填 **损耗原因**
- 系统自动算差额（实收 − 送货）和实收金额
- 移动模式（手机/平板）：每屏 3 条，只有商品名 + 大号实收输入框，支持扫码枪扫码定位并累加数量，适合仓库边收边录

### ④ 收尾：清理临时商品
录单时来不及建正式商品的，会以**临时商品**存在。每天收尾去「基础信息 → 别名与映射」：
- 能对应到标准商品的 → 点「转正」，关联到正式 SKU
- 确实是一次性的 → 保留或删除

## 四、新客入职 SOP（一次性，约 15 分钟）

```
第1步 建客户        →  第2步 导客户商品      →  第3步 报执行价
客户信息             客户商品                  商品报价
└ 客户 + 配送点      └ 快速同步粘贴报价单      └ 从客户商品池组装报价明细
```

1. **建客户**：「基础信息 → 客户信息 → 新增」，填名称、联系方式等；
   然后在客户的「**配送点**」里添加收货点（一个客户可以有多个配送点）。
2. **批量导客户商品**：「基础信息 → 客户商品」→ 打开「**客户商品快速同步**」弹窗：
   - 选客户，文本框里粘贴报价清单，**每行一条**，两种写法都行：
     ```
     土豆=黄心土豆     ← 客户叫法=系统内部商品名
     西红柿            ← 直接写内部商品名
     PG                ← 助记码也可以
     ```
   - 系统按名称/助记码自动匹配标准 SKU；没匹配上的行列出来，不影响其它行
   - 建议勾上「**转临时**」：没匹配到的自动存为该客户临时商品，之后按每日清单第④步转正
3. **生成报价**：「基础信息 → 商品报价」新建报价单，从该客户商品池组装明细、填执行价。
   - **频率**：只在签新客或调价周期（一般 **1–2 周**）做一次，不是每天

## 五、关键概念速查

| 概念 | 一句话解释 |
|---|---|
| SPU / SKU | SPU=标准商品（如"土豆"），SKU=具体规格（如"黄心土豆 10斤/箱"），编码 S+8位 |
| 客户商品池 | 这个客户能订哪些商品，以及他自己的叫法、起订量 |
| 临时商品 | 录单时现编的品，先用起来，之后转正 |
| 转正 | 把临时商品挂到正式 SKU 上，历史单据跟着更新 |
| 应收 / 实收 | 应收=送货单上的数量（不改）；实收=实际收到的数量（验收时填） |
| 执行价 | 客户实际结算的单价，来自报价单 |

**取价优先级**（录单时系统自动找价）：配送点覆盖价 > 客户报价 > 报价模板。

## 六、常见问题 FAQ

**Q：客户报的菜名系统里搜不到？**
先试助记码/简称；实在没有就录成临时商品，当天收尾时转正或让管理员补标准商品。

**Q：验收时发现送货单本身开错了怎么办？**
验收只管"实收"，送货单错误走订单修改流程，不要为了凑数乱填实收。

**Q：调价周到了，改哪里？**
「基础信息 → 商品报价」找到该客户报价单，批量调整明细价格并生效。

**Q：误删了客户商品怎么办？**
重新在「客户商品」里指派回该 SKU 即可；已生成的历史订单不受影响。
