# 验收模块订单明细视角重构设计（客户日一单 + 明细行=订单明细）

> 状态：🟢 已定稿（2026-09-08，用户确认「验收模块用回订单明细那种视角处理」后编写）
> 目标：验收模块全面对齐 D-055「订单明细=唯一真相」——**验收单=客户+配送日期一张，
> 明细行=订单明细行（配送点/订单号/变更标记为行属性）**，送货单/source_item 视角退役为历史只读。
> 关联：D-055 视图化（§十九 收尾二期已接通点单口径回写）、D-032 退货单（按 acceptance_item 引用，不受影响）。
> 决策编号：本文使用 **AC-x**（Acceptance）。

---

## 一、现状与问题（2026-09-08 查实）

验收服务内两条路径并存（`AcceptanceServiceImpl`）：

| 路径 | 建单 | 提交 | 撤销 | 使用场景 |
|---|---|---|---|---|
| 历史送货单口径（`deliveryOrderId != null`） | `createByDeliveryOrder`（仅 DELIVERED 送货单；A类=source_item 点级展开 / B·C类=送货明细行） | `updateStatusByDeliveryId(DELIVERED→ACCEPTED)` + `syncActualMirror` 占比分摊 | ACCEPTED→DELIVERED + 分摊清镜像 | D-055 前历史单（只读维护：撤销/退货仍可用） |
| D-055 点单口径（`deliveryOrderId == null`） | `createByCustomerPoint`（客户+日期+**点**，一维一验；应送行=订单明细） | `syncActualMirrorFromOrderDetails` 1:1 镜像 + `updateStatusByIds(CONFIRMED→ACCEPTED)` | ACCEPTED→CONFIRMED + 清镜像 | 现行唯一建单路径（入口=客户日总表点单区） |

问题清单：

| # | 问题 | 说明 |
|---|---|---|
| A1 | **维度偏细**：一客户一日 N 个配送点 = N 张验收单 | 单据量翻倍；客户日总表点单区要逐点生成；与「客户日报表」（客户+日期）主题错位 |
| A2 | **明细视图是「商品分组」** | 商品分组折叠视图是历史 A 类单（跨点展开）的产物；点单口径下组内常常只有本点行，视图噪音大，且看不到订单号/变更标记 |
| A3 | **「去验收」定位绑死送货单**：`locateBySaleOrder` 走 source_item 反查；订单列表按钮条件 `status==2` | D-055 后新订单停在 status=1（CONFIRMED→ACCEPTED 直跳），按钮对新流程基本失效；新视角下定位只需 客户+日期 |
| A4 | `fillSources`（来源对照列）依赖 source_item | 点单口径验收行**本身就是订单明细行**，无需来源对照；行上反而缺订单号/标记列 |
| A5 | 工作台待验收按 客户+日期+点 分组 | 与新维度不一致，应改 客户+日期 |
| A6 | 按点建单守卫对「无配送点客户」存在漏洞隐患 | `countByCustomerPointDate` 用 `delivery_point_id = #{deptId}`，dept 为 null 时 `= NULL` 恒不成立 |

**有利条件（零 DDL 的原因）**：
- `acceptance` 表已有 `delivery_date` 列（s20）；`acceptance_item` 已有 `sale_order_detail_id`、`customer_dept_id`；
- `SaleOrderDetailMapper#selectValidByCustomerDateForView(customerId, deliveryDate)` 已存在
  （点单全点视图在用，行带 订单号/配送点名/变更标记）；
- `submit/revoke` 的「点单口径」分支按 `deliveryOrderId == null` 判定，新维度天然复用，**回写代码零改动**。

## 二、核心决策

### AC-1 验收单维度 = 客户 + 配送日期（一张单/客户/日）

- 明细行 = 该客户当日全部订单明细行（跨配送点平铺，`customer_dept_id` 为行属性）；
- 表头 `delivery_point_id` 置 NULL（展示用「全部配送点」），`delivery_date` 照写；
- **按点录入体验保留**：明细编辑对话框内按配送点 tab 过滤行（与点单口径同 UI），文档维度不再拆点；
- 理由：①与订单明细唯一真相完全同构；②与总单打印（客户+日期）及客户日报表主题对齐；
  ③单据量降为 1/N；④退货/结算按 acceptance_item 行级引用，完全不受维度影响；
- 备选（未采用，留档）：保持按点一维一验，仅做视图统一——若业务要求按点签收强对齐再切换，
  服务方法签名预留 `customerDeptId` 可空参数即可支持。

### AC-2 应送行规则（继承 D-055 既有口径，不新增）

- 取 `selectValidByCustomerDateForView`（o.status>=1 且未删除，含标记行）；
- 退货行（change_type=3）：应送=0、实收=0，保留行展示（红色标记）；
- 加单行（change_type=1）：默认实收取订单明细 `actual_num` 镜像（现场已录），>0 则用之，否则按应送兜底；
- 换货行（change_type=2）：正常验收；
- 实收单价锁订单下单价快照，实收金额后端重算，合计=验收单 total_amount（结算依据不变）。

### AC-3 一客户日一验守卫（修 A6）

- 新增 `AcceptanceMapper#countByCustomerDate(customerId, deliveryDate)`：
  `where customer_id=# and delivery_date=# and delivery_order_id is null`——
  新口径验收单（无论按点历史遗留还是客户日）都计入，防止混维度重复建单；
- 重复建单提示带已有验收单号（先 `selectByCustomerPointDate` 查最新一张回显）。

### AC-4 建单路径收敛

- 新唯一建单入口：`AcceptanceService#createByCustomerDate(customerId, deliveryDate)` +
  `POST /acceptance/create-by-customer-date`（perm `acceptance:add`）；
- 删除 `createByCustomerPoint` + `POST /acceptance/create-by-point`（唯一调用方 view.vue 同步改）；
- `createByDeliveryOrder` + `POST /acceptance`（AcceptanceCreateDTO）**标 @Deprecated 保留**：
  历史 status=2 订单的「去验收」仍走旧定位与旧建单（不新建送货单，但历史日期可能还需补建验收），
  前端新流程入口不指向它；
- `expandByPoint/expandByDetail/syncActualMirror(占比分摊)/fillSources` 随旧路径保留（历史单只读维护用），
  注释标注「历史单专用，新单不进入」。

### AC-5 「去验收」定位改订单视角（修 A3/A4）

- `locateBySaleOrder` 重写为双分支：
  - **订单视角优先（新）**：订单行取 `customer_id + delivery_date + coalesce(customer_dept_id)` →
    `countByCustomerDate/selectByCustomerPointDate` 判该客户日是否已有验收单 → 返回
    `{customerId, deliveryDate, hasAcceptance, acceptanceId, acceptanceCode, acceptanceStatus}`；
  - **历史回退（旧逻辑原样保留）**：订单 status=2（已配送，历史单）走 source_item/送货明细反查送货单 → 验收单；
  - VO 新增 `customerId/deliveryDate`（订单视角必返），前端据此分流。
- 订单列表「去验收」按钮：显示条件 `status ∈ {1, 2}`（status=1 新流程主场景）：
  - status=1 → 跳验收页 `?customerId=&deliveryDate=&create=1`（无单时确认后直接建草稿）；
  - status=2 → 走旧 locate 逻辑（历史单）。

### AC-6 明细视图订单明细化（修 A2/A4）

- 验收明细行展示/录入改为**平铺订单明细行**：订单号 / 配送点 / 商品 / 规格 / 单位 / 应送 / 实收 /
  差异 / 原因 / 标记tag（加单/换货/退货） / 实收金额；
- **商品分组折叠视图删除**（历史单也平铺展示，行数据本来就有）；
- 行数据回填（服务层，防 N+1）：`AcceptanceItem` 加 transient `orderCode`、`customerDeptName`——
  按 `sale_order_detail_id` 批量反查（`selectByIdIn` 已有）+ 点名批量回填；
- 差异原因双向规则、实收防抖保存、确认验收、highlightOrder 定位等既有交互保留
  （highlight 按订单号匹配行）。

### AC-7 工作台与入口对齐（修 A5）

- `WorkbenchMapper#selectPendingAcceptance`：分组维度改为 客户+日期（去掉点分组），
  已验收判定改 `not exists (acceptance where customer_id+delivery_date, status=1)`——
  历史单 `delivery_date` 为 NULL 不会误匹配（s20 前的历史验收单该列为空，天然隔离）；
- 客户日总表：点单区「生成验收单」按钮从点 tab 移到**查询条（客户+日期级）**，调 create-by-customer-date；
  点 tab 内保留「打印点单」，验收入口收敛到查询条；
- 工作台待验收卡：跳转验收页带 `?customerId=&deliveryDate=`（列表行点击）。

### SQL

**无 DDL**（acceptance.delivery_date、acceptance_item.sale_order_detail_id/customer_dept_id 均已就位）；
不涉及菜单/权限变更（新接口沿用 acceptance:add）。

### 兼容与边界

- 历史 status=2 订单：去验收/查看/撤销/退货全链路不变（旧分支保留）；
- D-055 期间已建的按点验收单（delivery_point_id 非空）：照常查看/编辑/提交/撤销；
  同客户日再建客户日单会被 countByCustomerDate 拦截（测试数据如冲突，清理或先提交）；
- 退货单：引用 acceptance_item 行，两口径通用，零改动；
- 月结冻结（checkNotSettled）、撤销审计快照、revoke 原因必填：不变；
- 订单冻结语义不变：提交回写后订单 ACCEPTED（checkOrderEditable 冻结），撤销解冻。
