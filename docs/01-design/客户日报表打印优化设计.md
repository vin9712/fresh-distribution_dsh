# 客户日报表打印优化设计（模板解析服务化 + 回执式登记 + 当日批量打印）

> 状态：🟢 已定稿（2026-09-08，经用户确认方向后编写）
> 目标：让「打印客户日总表（总单 / 点单）」从**逐客户手工循环**变成**一次勾选、顺序出纸**，
> 并把模板选择权还给后端绑定解析、把「已打印」分界从开窗即登记改为真实打印回执。
> 关联：D-055 送货单视图化（`送货单矩阵总表与批次视图设计.md` §十八/§十九）、
> `打印模板通用数据结构与模板设计.md`（数据契约）、W0-4.1 票据、P1 绑定解析（D-048）、s24 预览增强。
> 决策编号：本文使用 **PT-x**（Print Today），不占用 D-0xx 序列。

---

## 一、背景与问题清单（2026-09-08 查实）

D-055 后打印链路已完整：页面选主体 → `POST /print/ticket` 签发票据（bizKey 绑定）→
新标签打开 JimuReport 视图 → 数据集回调 `/print/*`（票据强校验）→ 用户在报表页手动打印
（s24 注入 print-annotation.js 提供标注/直接打印）。但站在「文员每天早上要打完当天全部客户日报表」
的视角，存在 6 个问题：

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| P1 | 模板 ID 硬编码在前端（`TOTAL_MATRIX_TEMPLATE_ID` / `POINT_FLAT_TEMPLATE_ID`） | `order/batch/view.vue` | P1/D-048 的三级绑定解析（客户+点 > 客户 > 全局默认）**被 D-055 打印链路完全绕过**；s25 把总单默认切到长表模板（t_print_template id=13）后，页面仍打开宽表 2599…001；客户配专属模板不生效；换模板要改代码 |
| P2 | 一天 N 客户 ×（总单 + 各点单）要逐个「选客户→打印→切标签→报表页再点打印」 | `view.vue` handlePrint/handlePointPrint | **本需求核心痛点**：日报表打印是每天固定批量动作，现无批量入口 |
| P3 | 打印分界登记时机错误：`markDeliveryPrinted` 在 `window.open` 瞬间登记 | `view.vue` | 用户打开报表页后取消打印，「已打印」也翻转 → 配送前/配送后分界失真，直接影响「正常改单 vs 配送后变更」的业务判断（D-055 核心分界） |
| P4 | 候选模板接口只认历史单主体（`/order/delivery/{id}/print-candidates`） | PrintTemplateService | D-055 新主体无 bizKey 版解析/候选接口 |
| P5 | 数据集 api_url 硬编码 `http://localhost:8090`；s22/s25 未执行远端 | `jimu_report_db` | 换环境失效；远端报表取数仍是旧 URL |
| P6 | 双打印栈边界：JimuReport（A4）与 hiprint/本地打印助手（针式，W0-4.2/4.3 待硬件）并存 | — | 本次不合并；针式硬件到位后另走 W0-4.2/4.3 |

## 二、总体方案（一张图）

```
文员选日期 → 「当日打印」抽屉
  ├─ GET /order/delivery/print-manifest?deliveryDate=     ← 后端按订单明细(status≥1)聚合当天
  │     [{customer, 总单(bizKey,printed), 点单们(bizKey,printed)}]     打印清单（唯一数据源）
  ├─ 勾选（默认全选未打印）→ 开始打印 → 前端队列逐张：
  │     ① GET /print/resolve-template?bizKey=      ← 后端三级绑定解析（PT-1，替代硬编码）
  │     ② POST /print/ticket/batch（预取票据）
  │     ③ window.open /jmreport/view/{template.content}?...&ticket=
  │     ④ 报表页 print-annotation.js 在真实打印动作后 POST /print/receipt {ticket}（PT-3 回执）
  │     ⑤ 抽屉经 localStorage storage 事件收到回执 → 自动推进下一张（失败/跳过可手动）
  └─ 全部完成后刷新 manifest（printed 翻转）→ 分界可信
```

要点：**打印主体三元组不变**（`matrix:{客户}:{日期}` / `point:{客户}:{点}:{日期}`），
本次不新增打印主体形态；只把「模板选择、登记时机、批量动作」三件事做对。

## 三、详细设计

### 3.1 模板解析服务化（PT-1，对应问题 P1/P4）

**后端**：`PrintTemplateService` 新增方法 + `PrintController` 暴露接口：

```
GET /print/resolve-template?bizKey={bizKey}
perm: @ss.hasAnyPermi('order:delivery:print,print:template:list')
→ {
    "printForm": "MATRIX" | "FLAT",
    "templateId": <t_print_template.id>,        // = jimu_report 视图ID（content 列即视图ID）
    "templateName": "总单长表模板",
    "reportViewId": <content>,                  // 前端 open /jmreport/view/{reportViewId}
    "matchGlobalDefault": true|false,           // 未配客户级模板时 true（页面告警用）
    "candidates": [ ...同形态已发布模板（bind_type 升序）... ]
  }
```

- bizKey 解析（与 `PrintController#matrixBizKey/pointBizKey` 同一字符串契约，抽出公共解析器）：
  - `matrix:{customerId}:{date}` → printForm=`MATRIX`，customerId，deliveryPointId=null；
  - `point:{customerId}:{deptId}:{date}` → printForm=`FLAT`，customerId，deliveryPointId=deptId；
  - 其他前缀（`delivery:` 等）→ 400 `ServiceException("不支持的打印主体键")`。
- 解析复用 `printTemplateMapper.selectBindTemplate(customerId, deliveryPointId, printForm)`
  （P1 既有 SQL，零新查询）；候选复用 `selectPrintCandidates(customerId, printForm)`。
- `matchGlobalDefault` 口径与 `selectPrintCandidates` 一致：候选中无 bind_type<3 的模板即为回落全局默认。
- 无已发布模板 → 返回 200 + `templateId=null` + warning 文案（前端提示「未配置已发布模板」），
  **不抛 500**（批量队列要能跳过该项继续）。
- 实现落点：`PrintTemplateService#resolveByBizKey(String bizKey)`；把 bizKey 解析抽成
  `PrintBizKeys` 工具类（parse/format 双向），`PrintController` 的 `matrixBizKey/pointBizKey` 改为委托，
  保证签发与解析永不错位。

**前端**：
- `api/print/template.js` 新增 `resolvePrintTemplate(bizKey)`；
- `view.vue` 删除两个硬编码常量，`handlePrint`/`handlePointPrint` 改为：
  `resolvePrintTemplate(bizKey)` → 取 `reportViewId` → `issuePrintTicket({bizKey, templateId})` → open；
  `templateId=null` 时 `msgWarning` 并中止。
- 旧打印对话框（历史单 `delivery/index.vue`）不动，继续走 `/print-candidates`。

### 3.2 当日打印清单（PT-2）

**后端**：`DeliveryBatchService#selectPrintManifest(deliveryDate)` + `GET /order/delivery/print-manifest`：

```
GET /order/delivery/print-manifest?deliveryDate=2026-09-08
perm: @ss.hasAnyPermi('order:delivery:print,order:delivery:batch')
→ [ PrintManifestVO ]：
  customerId, customerName            // 客户（alias 优先，与点单表头口径一致）
  matrix:    { bizKey, printed }      // matrix:{customerId}:{date}，printed=countPrinted(客户,日期,NULL)
  points: [ { deptId, deptName, bizKey, printed, totalNum } ]
```

- 取数口径与点单完全一致（`o.status >= 1`、`d.is_deleted=0`、`o.is_deleted=0`）：
  新增 `SaleOrderDetailMapper#selectPrintManifestRows(deliveryDate)`——
  `SELECT DISTINCT o.customer_id, c.name, c.alias, COALESCE(d.customer_dept_id, o.customer_dept_id) dept_id, cd.name dept_name`
  （DISTINCT 而非 GROUP BY，天然满足远端 `ONLY_FULL_GROUP_BY`）；**纯退货行过滤留给矩阵取数口径**
  （manifest 只回答「有没有单」，有单即可打总单，与页面矩阵口径一致）。
- printed 批量判定：服务层逐项调 `countPrinted`（当天客户数 × 点数级循环，
  单日量级 ≤ 百级，可接受；不做 IN 批查以免 XML 复杂化）。
- 无订单的日期返回空数组；`deliveryDate` 缺参 400。

**前端**：`view.vue` 查询条新增「当日打印」按钮（只依赖 deliveryDate，选了客户也打全客户清单）+
新组件 `views/order/batch/printManifestDrawer.vue`：

- 加载 manifest → 树形/分组复选列表：客户行（总单复选 + 展开各点复选，点行带 `应送 N` 与「已打印」tag）；
  顶部「只看未打印」开关（默认开）与「全选未打印」；
- 「开始打印」：把勾选项平铺为队列（顺序：先全部总单后全部点单，或按客户分组——**按客户分组**，
  同客户的总单→点单连续，便于按客户核对纸面）；
- 逐张执行：resolve 模板 → 签发票据 → `window.open(reportViewId URL)` → 状态标「等待回执…」；
- **回执驱动推进**：报表页 print-annotation.js 真实打印后写
  `localStorage['print_receipt'] = JSON.stringify({bizKey, t})`，抽屉监听 `storage` 事件命中 bizKey
  即标「已打印」并自动开下一张；超时（45s）或用户点「跳过」→ 标「跳过」继续；「中止」随时可停；
- 队列结束：自动重拉 manifest 刷新 printed；汇总「成功 x / 跳过 y」。
- 单客户路径复用同一抽屉（传 `customerId` 过滤即可，不另做入口）。

### 3.3 打印回执时机修正（PT-3，核心正确性修复）

**原则：开窗不登记，真实打印动作才登记。**

**后端**：
- 新接口 `POST /print/receipt`，body `{ticket}`——** permitAll + 票据自证**（JimuReport 页面无 JWT，
  票据本身已绑定主体与签发人，语义与数据集回调同源同强度）：
  - `PrintTicketService#consumeForReceipt(String ticket)`：未用票据一次性领取、已用票据宽限期内取出，
    返回 `PrintTicketPayload`（无效/过期 → null）；
  - payload 有 `deliveryOrderId`（历史单）→ 忽略（历史单走旧 `/{id}/mark-printed`，不混写）；
    有 `bizKey` → 解析 bizKey → `deliveryBatchService.markPrinted(customerId, date, deptId?, templateId)`；
    bizKey 非法 → 返回 success 但不写库（回执永远 2xx，避免报表页报错打断打印）。
  - 操作者取 payload.username（无安全上下文）。
- `SecurityConfig`（lin-admin）把 `/print/receipt` 加入 permitAll（与三个数据接口并列）；
  **改了 lin-admin 模块 → 必须全量 `mvn install -DskipTests`**（DEV-ENV-NOTES 既有约定）。

**报表页（print-annotation.js）**：
- 在两个真实打印出口（预览条「打印(含标注)」`printAnno()` 与纸张预览弹窗「打印」）触发
  `frame.contentWindow.print()` 的同一函数里，追加 `notifyPrinted()`：
  读 URL `ticket` 参数 → `localStorage.setItem('print_receipt', JSON.stringify({bizKey, ticket, t:Date.now()}))`
  → `fetch('/dev-api/print/receipt', POST JSON)`（dev 代理 `/dev-api`→8090；**fetch 失败静默**，
  localStorage 事件已够抽屉推进，登记接口失败仅日志）。
- API 前缀自适应：页面 URL 同时可能经 dev 代理（`/jmreport` 前缀）或生产 Nginx 同源反代，
  统一取 `window.location.origin + (window.location.pathname.startsWith('/jmreport') ? '/dev-api' : '')`？
  ——不行，生产无 /dev-api。**定稿：fetch 相对路径 `./receipt` 不改，改为绝对同源 `/print/receipt`
  直连后端**：报表页由后端 8090 直接伺服（生产 Nginx 同路径反代 /jmreport 与 /print 同源）；
  dev 下报表页经 vite 代理，`/print/receipt` 未被代理 → **在 vite.config.js 补一条 `/print` 代理**
  （与 /jmreport 同写法，target 后端），生产侧 Nginx 增加同路径反代（DEPLOY.md 补一行）。
  这样 annotation JS 永远 `fetch('/print/receipt')`，零环境判断。
- **缓存版本**：js_str 引导 URL `print-annotation.js?v=10` → `?v=11`（新增 s26 SQL，见 §四）；
  s25 长表模板 js_str 若无引导则一并补上。

**前端 view.vue**：`handlePrint`/`handlePointPrint` 中的 `markDeliveryPrinted(...)` 调用删除，
改在开窗前仅刷一次 `loadPrintState()`（开窗后由回执翻转）。E2E `e2e-d055-closeout.mjs`
「点单打印后已登记分界」断言同步改掉（改为直接 POST /print/receipt 验证，见 §五）。

### 3.4 票据批量签发（PT-4，可选优化，本期实现）

```
POST /print/ticket/batch   body { bizKeys: ["matrix:10:...", ...] }  // ≤50，超出 400
→ { tickets: { "matrix:10:2026-09-08": "ptk_...", ... } }
```

- 队列预取：打印第 N 张时预签第 N+1 张，消除逐张往返；语义与单签完全一致（各自 TTL）。
- 权限同 `/print/ticket`。
