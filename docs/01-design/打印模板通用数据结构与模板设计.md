# 打印模板通用数据结构与 JimuReport 模板设计（总单 / 点单）

> 目标：重新定义 总单（MATRIX）与 点单（POINT）的打印数据结构，使其成为**通用契约**——
> 版式全部交给 JimuReport 的 Excel 设计器（`打印模板管理 → 设计`）自由调整，数据接口只负责给"足够通用、
> 语义稳定"的字段。本文给出：统一数据契约、字段字典、三个可直接入库的模板 json_str 样例、设计器操作指引。
>
> 适用版本：JimuReport 2.0.0（`jimureport-spring-boot3-starter-fastjson2`）
> 关联：D-055 送货单视图化；现模板种子 s6_2（FLAT 点单）/ s18（MATRIX 总单）/ s22（参数）/ s24（view 增强）

---

## 一、设计原则

1. **数据与版式分离**：接口输出"语义字段"（品名/数量/配送点…），模板决定摆哪里、怎么画。改版式=改模板，不动代码。
2. **两种数据形态**：
   - `head`：单值数据集（`${hd.xxx}` 绑定）——标题/客户/日期/合计等；
   - `rows`：列表数据集（`#{dd.xxx}` 绑定）——明细行。
3. **总单给两种明细形态，模板按需选**：
   - **宽表（兼容套打）**：一行菜品、c1~cN 固定槽位（现方案），列位绝对稳定，适合针打套打；
   - **长表（通用推荐）**：一格一行（菜品×配送点 全交叉），配合 JimuReport **横向动态列分组**
     （`#{dc.groupRight(deptName)}` + `#{dc.dynamic(num)}`），配送点数量变化**模板零改动**。
4. **合计由后端算好放进数据**（head.totalXxx / row 行合计），设计器只管摆位置，不写公式。
5. **新字段只增不改名**：旧字段全部保留，老模板不失效。

## 二、统一响应骨架

所有打印数据接口（`/print/**`）统一为：

```json
{
  "meta": {
    "reportType": "MATRIX | POINT | PICK",
    "bizKey": "matrix:10:2026-09-03",
    "printTitle": "丽宫总单",
    "printTime": "2026-09-05 08:00",
    "paper": { "w": 210, "h": 297, "layout": "portrait" },
    "warnings": ["本批次无布局快照，列按当前启用配送点实时推导"]
  },
  "head":    { "…单值字段…": "见字段字典" },
  "columns": [ "…总单专用：配送点列定义…（点单无此节）" ],
  "rows":    [ "…列表行…见字段字典" ]
}
```

- JimuReport 数据集注册时：`head` → 单值数据集（`is_list=0`），`rows` → 列表数据集（`is_list=1`），
  `columns` → 列表数据集（`is_list=1`，仅总单长表模板需要）。
- 现有转换器 `deliveryDataConvertAdapter` / `deliveryRowsConvertAdapter` 已支持
  `{head}` → 单行数组、`{rows}` → 列表；`columns` 需要第三个转换器或复用 rows 适配器（见 §六）。

## 四、总单（MATRIX）数据结构

### 4.1 head 字段字典（数据集 `hm`，绑定 `${hm.xxx}`）

| 字段 | 类型 | 说明 | 现状 |
|---|---|---|---|
| printTitle | string | "丽宫总单"（可覆盖） | ✅ |
| bizKey | string | `matrix:{customerId}:{date}` | 新增 |
| customerId / customerName | long/string | 客户 | ✅ |
| deliveryDate | string | 配送日期 | ✅ |
| batchId | long | 配送批次 | 新增 |
| colBlockNo / totalColBlocks / colBlockLabel | number/string | 列块分页（宽表套打用） | ✅ |
| totalQuantity | number | 总量 | ✅ |
| totalKinds | number | 品项数 | 新增 |
| pointCount | number | 配送点数 | 新增 |
| layoutVersion | number | 布局快照版本（null=实时推导） | ✅ |
| layoutDerived / identityOk | bool | 推导标记/恒等式自检 | ✅ |
| warnings | string[] | 告警 | ✅ |
| remark / printTime | string | 备注/打印时间 | ✅/新增 |

### 4.2 columns 字段字典（数据集 `hc`，长表模板的横向分组表头来源）

| 字段 | 类型 | 说明 |
|---|---|---|
| seq | number | 列序（1 起，决定横向顺序） |
| deptId / deptCode / deptName | long/string | 配送点 |
| hasData | bool | 当日有单 |
| adHoc | bool | 停用点临时补列 |
| empty | bool | 套打占位空列 |

### 4.3 宽表 rows（数据集 `dm`，兼容套打——现方案通用化）

一行一个菜品，`c1~cN` 固定槽位（N = printConfig.colsPerPage，模板槽位数必须一致）：

```json
{
  "seq": 1, "productName": "京包菜", "spec": "", "unit": "斤", "remark": "",
  "c1": 4, "c2": 5, "c3": null, "c4": null, "c5": null, "c6": null,
  "rowTotal": 9
}
```

表头列名在 head：`c1Name ~ c6Name`。**约定**：接口按 colsPerPage 输出槽位、空槽 null；
模板设计时槽位格子逐个绑 `${hm.c1Name}` / `#{dm.c1}`。

### 4.4 长表 rows（数据集 `dc`，通用推荐——菜品×配送点 **全交叉**）

一行一个"格"，跨全激活配送点全交叉输出（无数据的格 num=null，保证横向动态列"第一条数据完整"规则）：

```json
{
  "seq": 1,                       // 菜品行序（同菜品多格相同；设计器可按此纵向合并）
  "productName": "京包菜", "spec": "", "unit": "斤", "remark": "档①",
  "deptSeq": 1, "deptId": 2, "deptName": "点心", "deptCode": "LG1000003",
  "num": 4,                       // null=当日无此菜（渲染为空白）
  "rowTotal": 9                   // 该菜品行合计（后端算好，组尾/行尾直接绑）
}
```

> 全交叉的重要性：JimuReport 横向动态分组要求**第一条数据包含全部分组值**，且分组顺序取首次出现序。
> 后端按 deptSeq 升序全交叉输出，列序稳定、规则天然满足；若只想输出有值格，需自行承担动态列漂移风险。

### 4.5 总单长表模板 json_str（横向动态列，配送点数量变化模板零改动）

结构：hm 表头（打印标题/客户/日期/列块标签）→ hc 横向表头（`groupRight` 扩展）→ dc 数据行（`dynamic` 跟随）→ 行合计。

```json
{

  "querySetting": { "izOpenQueryBar": false, "izDefaultQuery": true },
  "recordSubTableOrCollection": { "group": [], "record": [], "range": [] },
  "printConfig": { "paper": "A4", "width": 210, "height": 297, "definition": 1, "isBackend": false, "marginX": 8, "marginY": 10, "layout": "landscape" },
  "hidden": { "rows": [], "cols": [] },
  "queryFormSetting": { "useQueryForm": false, "dbKey": "", "idField": "" },
  "dbexps": [], "dicts": [], "freeze": "B4",
  "dataRectWidth": 1000,
  "isViewContentHorizontalCenter": false,
  "autofilter": {}, "validations": [],
  "cols": {
    "0": { "width": 45 }, "1": { "width": 160 }, "2": { "width": 70 }, "3": { "width": 50 },
    "4": { "width": 90 }, "len": 30
  },
  "area": { "sri": 0, "sci": 4, "eri": 0, "eci": 4, "width": 100, "height": 25 },
  "pyGroupEngine": false,
  "submitHandlers": [],
  "hiddenCells": [], "zonedEditionList": [],
  "rows": {
    "0": { "cells": { "0": { "merge": [0, 4], "text": "${hm.printTitle}", "style": 1 } }, "height": 34 },
    "1": { "cells": {
      "0": { "merge": [0, 1], "text": "配送日期：${hm.deliveryDate}" },
      "2": { "text": "列块：${hm.colBlockLabel}" },
      "3": { "merge": [0, 1], "text": "合计：${hm.totalQuantity}（${hm.totalKinds} 项 / ${hm.pointCount} 点）" } }, "height": 22 },
    "2": { "cells": {
      "0": { "text": "序号", "style": 1 }, "1": { "text": "菜品", "style": 1 },
      "2": { "text": "规格", "style": 1 }, "3": { "text": "单位", "style": 1 },
      "4": { "text": "#{hc.groupRight(deptName)}", "style": 1 } }, "height": 24 },
    "3": { "cells": {
      "0": { "text": "#{dc.seq}" }, "1": { "text": "#{dc.productName}" },
      "2": { "text": "#{dc.spec}" }, "3": { "text": "#{dc.unit}" },
      "4": { "text": "#{dc.dynamic(num)}", "style": 1 } }, "height": 22 },
    "4": { "cells": {
      "0": { "merge": [0, 3], "text": "合计" },
      "4": { "text": "${hm.totalQuantity}" } }, "height": 24 },
    "len": 100
  },
  "rpbar": { "show": true, "pageSize": "", "btnList": [] },
  "fixedPrintHeadRows": [2, 3],
  "fixedPrintTailRows": [],
  "displayConfig": {}, "background": false, "name": "sheet1",
  "styles": [ { "align": "center" }, { "bgcolor": "#d9e1f2", "align": "center" } ],
  "freezeLineColor": "rgb(185, 185, 185)",
  "merges": [], "excel_config_id": "2599000000000000001"
}
```

关键绑定说明：

- `#{hc.groupRight(deptName)}`：表头格横向动态分组——每个配送点扩展成一列（箭头向右）；
- `#{dc.dynamic(num)}`：数据格跟随上方横向分组扩展（设计器里勾选"横向分组字段"自动生成）；
- `fixedPrintHeadRows: [2,3]`：表头两行跨页重复打印；
- 纵向合并同菜品的行：设计器中选中 B 列数据格 → 数据设置选"分组"（`group(...)`）即按品名合并；
- 数据集：`hm`（head）、`hc`（columns）、`dc`（rows 全交叉），端点都指向 `/print/deliveryMatrixData`
  （该接口已同时返回 head/columns/rows；`rows` 需按 §六切换为全交叉长表输出）。

### 4.6 总单宽表模板（兼容套打，槽位式）

与现行 s18 相同骨架（`#{dm.c1}`~`#{dm.c6}` + `${hm.c1Name}`），新增可选绑定：
`#{dm.rowTotal}`（行合计，替代 `${hm.totalQuantity}` 之外更细的行小计）、`${hm.totalKinds}`、`${hm.pointCount}`。
不再赘述完整 JSON，字段见 §4.1/§4.3。

## 五、Excel 设计器操作指引（改版式速查）

| 想改什么 | 在设计器里怎么做 |
|---|---|
| 改文字/字体/颜色 | 选中格子 → 顶部工具条（字体/字号/加粗/颜色/边框） |
| 改列宽/行高 | 拖列线 / 行线；精确值在右键"单元格设置" |
| 调列顺序 | 剪切单元格内容到目标列（数据格 `#{dd.xxx}` 可随意摆放，逐格绑定） |
| 加一列固定文字 | 直接在空白列输入文字，如"签收人" |
| 加合计/小计 | 单值合计绑 `${hd.totalAmount}`；行小计绑 `#{dd.amount}`；分组小计用"组内小计"（官方文档：横向分组下方单元格跟随扩展/横向组内小计） |
| 总单配送点列增减 | 长表模板**零改动**（groupRight 自动扩展）；宽表模板需槽位数一致（改 colsPerPage 时同步改模板） |
| 纸张/边距/方向 | 工具条"纸张设置"（写入 printConfig，view 页工作台/预览自动跟随） |
| 预览 | 保存后系统内打印预览（含标注工具），或"预览"按钮 |

## 七、边界与约束

1. **横向动态列"第一条数据完整"规则**：长表必须全交叉输出（后端保证），列序按 deptSeq 稳定排序。
2. **宽表套打槽位**：colsPerPage 变化时模板槽位必须同步改（这是宽表方案唯一的耦合点，也是它列位绝对稳定的代价）。
3. **多级表头**：横向动态分组最多 3 级（如 配送点→订单），够用但别堆更深。
4. **金额/数量格式**：设计器里单元格可设数值格式（千分位/小数位），后端只给原始 number。
5. **打印预览标注层**（s24 增强）对新模板自动生效，无需额外处理。
