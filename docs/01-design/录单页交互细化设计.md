## 一、需求背景

录单页（`order/sale/detail.vue`）是文员使用频率最高的页面，本次针对四个环节做交互固化：
客户选择与锁定、订单编号生成、草稿自动保存、最近订单的浏览与复制。

## 二、现状代码盘点

| 环节 | 现状 | 问题 |
|---|---|---|
| 客户联动 | 页面只暴露「送货单位(配送点)」下拉，客户由配送点带出；常用面板有"未选客户"提示 | **明细表格未锁**——不选配送点也能手敲商品行 |
| 订单编号 | 后端 `generateOrderNo(refresh, currentCode)` 已支持 peek(预览不占号)/相同则保持 | **前端刷新漏传 `currentCode`**（只传 `refresh:true`）→ 点一次必 +1 浪费号段；且后端仅对比内存序列 `biz_code_seq`，未校验 `t_sale_order.code` 实际占用 |
| 自动保存 | 草稿机制已存在（`utils/saleDraft`），但纯 localStorage | 换电脑/清浏览器缓存即丢失 |
| 最近订单 | 点击历史单 → 弹"是否确认变更" → **直接把历史单替换进当前表单** | 新单数据被顶掉，只能靠草稿横幅找回；无纯"浏览"模式；无复制操作 |

## 三、定稿规格

### 3.1 客户 / 配送点的选择与锁定

- **粒度 = 客户 + 配送点整体锁定**（2026-02 调整：未录入商品前允许直接改选配送点，明细自动清空重取价；录入商品后才整体锁定）：
  - 客户**无下属配送点** → 只传客户本身（无需选配送点）
  - 客户**有配送点** → 必须以配送点为准录入
  - 同一客户下切换不同配送点，**也算更换**：需整体清空重选（清明细、重取价、重新分配编号）
- 选定后客户/配送点均置灰不可改；要换必须走「重开新单」类入口，不允许半途只改表头。
- 明细区**门禁**（默认方案，业务未明确反对）：未选定客户(+配送点)前，商品搜索与加行操作禁用并给出引导提示"请先选择送货单位"。

### 3.2 订单编号规则

- 编号**只能系统生成，禁止手动修改**（输入框只读）。
- 生命周期模型：
  1. 进入新单页 → 显示下一个可用号（peek，**不占号**）
  2. 点「刷新」→ 后端判断：该号已在数据库存在 ⇒ +1 取新号；不存在 ⇒ **维持原值**
  3. **提交成功那一刻才真正占号**
- 提交时校验唯一性：若提交号已被占用，提示"订单编号已被使用，请点击刷新获取新编号"，不落库。
- 改造点：
  - 前端 `refreshOrderCode()` 补传 `currentCode`
  - 后端占用判断从"对比内存序列"升级为"查 `t_sale_order` 是否存在该 code"（含逻辑删除行）

### 3.3 草稿自动保存（升级后端）`[2026-09-19 补充]`

- 触发时机不变：明细变更防抖保存（~1.5s）、失焦、离开页面。
- 存储：**本地 localStorage + 后端草稿表双写**，恢复时以后端为准（更新时间新的赢）；后端为主、本地兜底断网场景。
- 草稿维度：新单按 `customerDeptId` 挂钩；编辑已有单按 `orderId` 挂钩。
- 提交成功或确认放弃时清除对应草稿。
- 与 §3.5 联动：**浏览模式期间暂停草稿写入**，防止浏览动作污染新单草稿。
- **草稿门禁（`[2026-09-19]`）**：不满足录单前置条件时不生成草稿，避免草稿箱出现半成品：
  - 未选送货单位 → 不落草稿；
  - 客户启用班次但未选班次 → 不落草稿；
  - 草稿 payload 补存 `shiftCode`（s35 遗漏）与 `baseUpdateTime`（载入时订单 updateTime 基线）。
- **草稿箱陈旧清理（`[2026-09-19]`）**：打开草稿箱/刷新恢复横幅时核对并清理旧数据：
  - 无送货单位，或启用班次的客户缺班次 → 无效；
  - **同编号订单已在服务端被保存/推进** → 旧数据：新单草稿（无 orderId）编号已落库即清；
    编辑草稿若订单已非草稿态、或 `updateTime` 与草稿基线 `baseUpdateTime` 不一致即清；
  - 命中即本地 + 后端一并删除；核对接口 `GET /order/sale/by-codes?codes=...`（只读，返回 id/status/updateTime）。
  - 配套：后端补齐 `update_time` 维护（create/update/状态变更三处），使基线比对可用。

### 3.4 最近订单面板定位（澄清）`[2026-09-19 调整]`

- 最近订单查询是**独立的**：自带客户筛选条件，与当前表单所选客户无强制联动。
- 用途定位：客户每天订单内容大同小异，主要供**给客户报数时预览**和**复制到新单**两个动作。
- **状态范围（2026-09-19）**：不再只列草稿，默认展示「**草稿 + 已确认**」（`statuses=[0,1]`），
  面板提供状态筛选（表单内带「**状态**」label 的搜索条件，与天数/客户/搜索词对齐）：
  `草稿+已确认`（默认）/ `仅草稿` / `仅已确认` / `全部`；列表新增「状态」列
  （复用 `orderStatusCell`，与订单列表页状态/单据图标口径一致）。
  后端 `/order/sale/recent/list` 新增可选 `statuses` 参数（逗号分隔），不传默认 `0,1`。

### 3.5 浏览 / 编辑无感切换（预览历史订单）`[2026-09-19 重写]`

- 点击右侧「最近」中的历史订单：**不再弹「收起新单？」模态**，直接静默暂存当前工作区并载入目标单；
  按订单状态自动决定形态：
  - `status=0` 草稿 → **编辑草稿**（可改可存，改动自动保存到该单草稿）
  - `status=1` 已确认 → **只读**，订单卡模式条提供「**撤回并编辑**」（就地撤回为草稿后转可编辑，
    不必再回订单列表；后端可撤回预检失败时按接口错误提示）
  - `status>=2` → 只读快照
- 顶部三条大 alert（浏览模式 / 正在编辑已有草稿 / 已确认只读）合并为**订单卡内一条轻量模式条**：
  `编辑草稿【单号】` / `只读浏览【单号】` / `只读·已确认【单号】` + 右侧「返回上一张单/我的新单」。
- 暂存与返回：
  - 首次离开录入态时暂存工作区（并先落盘草稿，避免 5s 防抖窗口内的改动只留在内存）；
  - 浏览态内切换历史单**不覆盖**原暂存；
  - 模式条「**← 返回我的新单 / 返回上一张单**」一键恢复，数据原样恢复；
  - 只读态**自动保存暂停**，编辑态照常。
- **左右联动（`[2026-09-19]`）**：
  - 当前打开的订单若在右侧「最近」列表中，对应行高亮（左侧蓝色色条 + 加粗），列表刷新/切筛选重载后仍保持；
    未打开订单（新单）或订单不在当前筛选结果中时不高亮。
  - 点击右侧打开已有单后，左侧**做单区滚动条复位到顶部**（不沿用上一张单的滚动位置）：
    - 做单区整体滚动条在 `.order-card .el-card__body`（订单信息+表头+明细），直接 `scrollTop=0`；
    - 明细表若自身可滚（小视口/多行），还需在替换 `orderDetailList` 前 `await xTable.clearScroll()`
      （vxe 在数据变更后会 `restoreScrollLocation` 回 `lastScrollTop`，必须先清零）。
- **配送日期变更确认不误弹（`[2026-09-19]`）**：打开一张跨配送日期的单（编辑草稿 / 只读浏览 /
  复制为新单 / 返回暂存）会以编程方式改 `orderForm.deliveryDate`，旧逻辑会误当成用户改期而弹
  「配送日期已从…改为…」确认框。现于所有程序性赋值后调用 `suppressDeliveryDateWarn()`（标志由
  `orderForm.deliveryDate` watcher 消费，`nextTick` 兜底清除），**仅用户手改日期仍提示**。

### 3.6 复制操作（当前单 → 新单）`[2026-08-29 调整]`

- 按钮位置：录单页**底部工具栏**，在「重置 / 保存」旁边（原先放在浏览工具条上，因与“空工作区直接进编辑模式”新规则冲突而搬迁）。
- **准入门槛**（已改）：不再要求“工作区为空”，而是**当前打开着一张已保存的单**即可：
  - 只读态（浏览/已确认/已验收/已结算）→ 来源 = 当前这张单
  - 编辑草稿态 → 来源 = 当前这张草稿单
  - 空白新单（未保存）→ 无来源，按钮不显示
- **防丢数据**：点击时若会丢弃内容则先二次确认——① 浏览/只读态下已收起的工作区；② 编辑态下当前订单的未保存改动。
- 复制动作用（已确认）：
  - 历史订单的**商品 + 数量**整体灌入新单工作区；**单价不照搬历史值，逐行按当前执行价重新取价**（`[2026-08 W0-1]` 仅客户正式报价单一口径，未命中空价走手工定价）
  - 送货日期按规则重算（15 点前=今天，之后=明天）
  - 订单号按 §3.2 重新分配
  - 复制完成后立即回到录入态（新单）
- 同一张历史订单可多次复制（服务不同日期/不同配送点的相似订单）。

## 四、开发改造清单（建议顺序）

1. 后端：草稿表 `t_sale_order_draft`（key、payload JSON、update_time、user_id）+ 保存/读取/删除接口
2. 后端：`generateOrderNo` 占用校验改为查库 + 前端补传 `currentCode`
3. 前端：表头锁定逻辑（客户+配送点整体锁、无配送点客户只锁客户）+ 明细区门禁
4. 前端：浏览模式改造（替换式加载 → 收起/恢复模型 + 「返回我的新单」按钮 + 暂停自动保存）
5. 前端：「复制为新单」按钮 + 空工作区判定 + 灌入逻辑
