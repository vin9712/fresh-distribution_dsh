# 送货单客户维度设计

> **状态**：🟢 新增设计（2026-08-29），承接基线《[销售订单与送货单关系设计](../销售订单与送货单关系设计.md)》D-001~D-037 与《[订单-送货-验收链路详细设计](订单-送货-验收链路详细设计.md)》，新增决策 **D-038 ~ D-042**。
>
> **一句话主张**：送货单的第一维度是**客户**（客户 + 配送日期），不是订单、不是配送点。因此送货单口径必须在**客户管理页可见、可配、可查**，生成动作必须先给出**客户维度的待生成清单**再确认。

---

## 一、为什么客户是主维度

| 事实 | 出处 | 推论 |
|---|---|---|
| 组单策略挂在客户上（`t_customer.doc_scope_type` / `doc_merge_same_item`），配送点不覆盖 | D-015 | 决定"出几张单、怎么并行"的是客户，不是点 |
| 批次唯一键是 `unique(customer_id, delivery_date)`，策略在生成瞬间快照进批次 | §3.2① / D-016 | 送货单的最小处理单元 = 客户 + 日期 |
| 送货单 = 客户（+ 可选配送点）当日的一张纸；A 类总单 `delivery_point_id=NULL` | §3.2② | 点是"客户之下"的分组维度 |
| 补单/作废重算/幂等判定全部按 客户+日期 计算（`selectMissedConfirmedOrders`） | D-021/D-022/D-023/D-025 | 不存在"按某张订单生成"，勾选订单只用于定位客户+日期 |
| 打印模板三级绑定 = 配送点 > 客户 > 默认；客户日总表、月结均按客户 | D-027/D-028、`PrintTemplate.bindType` | 下游动作同样以客户为锚 |

**结论**：订单是原料，点是分组，**客户才是送货单的主人**。凡是"生成送货单"的入口，都必须让人先看清"哪些客户、各出几张、并了哪些单、会不会作废已有单"。

## 二、四层模型（客户视角）

```text
L1 客户策略      t_customer.doc_scope_type / doc_merge_same_item      ← 客户管理页配置（长期、跨日期）
                        │ 生成瞬间快照（D-016：批次期内不再变）
L2 当日批次      t_delivery_batch  unique(customer_id, delivery_date) ← 客户+日期一条，锁死策略
                        │ 按 scope_type 分组
L3 送货单        t_delivery_order  A类1张(点=NULL) / B·C类每点1张      ← doc_kind 0正常/1补充，predecessor 链
                        │ 明细合并（D-024 不同价必拆行）
L4 来源台账      t_delivery_source_item  订单行 → 送货行 分配量        ← 幂等、补单、验收归属的唯一真相
```

### 客户维度口径矩阵

| 客户类型 | `doc_scope_type` | 一个「客户+日期」出几张单 | 明细行 | 验收 | 备注 |
|---|---|---|---|---|---|
| A 类（统一配送） | `CUSTOMER_DATE` | **1 张**跨点总单（`delivery_point_id=NULL`） | 同商品跨点合并成一行（点维度只留在 L4） | 总单明细按「点×商品」展开录入 | 适合"一个客户一辆车送到总仓" |
| B/C 类（按点配送） | `DELIVERY_POINT_DATE`（默认） | **每个配送点 1 张** | 点内合并 | 单内即点，直接录 | 现状行为 |
| 任意 | `doc_merge_same_item=false` | 同上 | 一订单行一行（不合并且不同价不拆） | 同上 | 需要按订单行对货的客户 |

> 补充单（`doc_kind=1`）与作废重建（`predecessor_id`）都发生在**同一客户+日期**内部，不跨客户。

## 三、生成入口收敛（全部落到 客户+日期）

| 入口 | 位置 | 处理维度 | 是否先预览 | 优先级 |
|---|---|---|---|---|
| 「选订单 · 生成送货单」抽屉 | 录单页底部 | 客户（+日期） | 抽屉内勾选即清单，二次确认 | 主路径 |
| 「本客户订单已录完 · 出送货单」 | 录单页底部 | 单客户+日期 | 二次确认 | 主路径 |
| **「生成送货单」（按日期）** | **送货单据页** | **当日全部有遗漏的客户** | **✅ 本次新增：客户维度待生成清单 → 确认（D-039）** | 批量收口 |
| **「送货单」视图** | **客户管理页行操作（D-040）** | **单客户+日期** | **✅ 本次新增：同一预览接口带 `customerId`** | 客户维度查补 |
| 定时窗口 23:30 / 06:00 | `ScheduledTasks` | 逐客户（内部同 preview 判定） | 否（兜底，异常进工作台告警 D-037） | 兜底 |

### 三态分支（客户维度判定，预览与生成同一套代码）

```text
V = 该客户当日未作废送货单（selectActiveByCustomerAndDate）
├─ V 为空                      → CREATE     正常生成（doc_kind=0）
├─ V 全部 PENDING（未打印）     → REBUILD    作废重建（D-022）：原单作废+释放分配，按当日【全部】已确认订单重建
└─ V 含 PRINTED / DELIVERED    → SUPPLEMENT 补充单（D-023）：原单不动，仅遗漏订单另出 doc_kind=1
```

## 四、交互：生成 → 客户维度待生成清单 → 确认（D-039）

**旧行为**：选日期 → `ElMessageBox.confirm("将为配送日期 X 生成送货单…")` → 直接写库。人只看到一句话，看不到"会给哪些客户出几张单、会不会作废我已打印的单"。

**新行为**（三步式）：

1. **选日期**：送货单页顶部日期 + 「生成送货单」→ 调 `GET /order/delivery/group-preview?deliveryDate=`
2. **看待生成清单**（一行 = 一个客户，可展开）：
   - 汇总条：待生成客户 N 个 · 待并入订单 M 张 · 预计生成 K 张 · 明细 R 行 · 金额 ¥X
   - 客户行：客户名 / 组单策略（跨点总单·每点一单）/ 处理方式 tag（正常生成 / **作废重建** / **补充单**）/ 待并入订单数 / 预计张数 / 金额
   - 展开：待并入订单（单号、配送点、行数、金额）+ 既有有效单（单号、点、状态、打印次数）
   - 警示条：`作废重建` 会作废哪几张未打印单；`补充单` 因原单已打印/已送达；**当日未确认草稿 N 张不会进入本次生成**（D-042）
   - 空态：「当日订单均已生成送货单，无需再生成」→ 确认按钮禁用
3. **确认生成**：按钮上直接写「确认生成（预计 K 张）」；调既有 `POST /order/delivery/generate/{date}`，结果在弹窗内如实回显（新单号 / 幂等跳过 / 失败），列表同步刷新

**一致性保证**：预览与生成共用 `DeliveryGenerationServiceImpl` 的同一套私有方法（`groupRowsByPoint` + `mergeRows` + 三态判定），杜绝"预览 3 张、生成 5 张"。预览只读：不 UPSERT 批次、不用 `FOR UPDATE`、不写任何表。

## 五、客户管理页的体现（D-040）

| 位置 | 内容 | 目的 |
|---|---|---|
| 列表列 | **组单策略**（跨点总单 / 每点一单 tag）、**相同商品合并**（是/否） | 送货单口径不用点进编辑框才看得到 |
| 筛选 | 按组单策略筛选（后端 `selectCustomerList` 支持 `docScopeType`） | 快速圈出"哪些客户走总单" |
| 表单 | 保留两字段 + 增加生效时机说明（D-041） | 改策略前知道影响范围 |
| 行操作「送货单」 | 客户维度抽屉：日期 → 策略来源 → 待生成清单 → 当日既有单 → 「生成/补单」 | 客户视角查单、补单，不必去送货单页翻筛选 |

### 抽屉结构（`partner/customer/customerDeliveryDrawer.vue`）

```text
客户：{name}   配送日期：[date]
├─ 组单策略：跨点总单｜来源：当日批次快照（已锁定，改客户配置不影响本日）   ← 已建批次
│           每点一单｜来源：客户当前配置（尚未建批次，本日按此生成）        ← 未建批次
├─ 待生成清单（group-preview?customerId=&deliveryDate=）：同送货单页客户行 + 展开
├─ 当日送货单（/order/delivery/list?customerId=&deliveryDate=）：单号/点/状态/打印次数/补充单 tag
└─ 底部：〔生成 / 补单〕→ POST /order/delivery/generate/customer/{customerId}/{date}（幂等）
```

## 六、接口契约（增量）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/order/delivery/group-preview?deliveryDate=&customerId=` | `order:delivery:add` / `generateCustomer` / `list` 任一 | **新增**：客户维度待生成清单预览（`customerId` 空=当日全部客户）；只读 |
| POST | `/order/delivery/generate/{deliveryDate}` | `order:delivery:add` | 既有：按日期逐客户幂等生成（预览确认后调用） |
| POST | `/order/delivery/generate/customer/{customerId}/{deliveryDate}` | `order:delivery:add` | 既有：单客户生成/补单（客户管理抽屉复用） |
| GET | `/order/delivery/list?customerId=&deliveryDate=` | `order:delivery:list` | 既有：客户当日送货单（抽屉下半区） |

### `DeliveryGeneratePreviewVO`（返回体）

```text
deliveryDate, customerCount, sourceOrderCount, expectedDeliveryCount, expectedDetailCount,
totalAmount, rebuildCount, supplementCount, draftOrderCount, draftOrderCodes[], customers[]
  └ CustomerPreview: customerId, customerName, scopeType, scopeDesc, mergeSameItem,
                     action(CREATE|REBUILD|SUPPLEMENT), actionDesc, actionTip,
                     expectedDeliveryCount, expectedDetailCount, totalAmount,
                     orders[](OrderPreview: id, code, customerName, customerDeptName,
                               deliveryDate, amount, itemCount, rebuildCovered),
                     existingOrders[](ExistingPreview: id, code, status, statusDesc,
                                      printCount, docKind, deliveryPointName)
```
