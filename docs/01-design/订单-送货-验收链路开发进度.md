## 一、目标一句话

把「订单→送货→验收」从**按客户+日期推断关联**的现状，改造为**来源显式建模**的三层模型：
**配送批次（客户日总表，采购配货用）→ 外部送货单（客户签收/验收凭证）→ 打印渲染**；
验收实收**落到配送点粒度、归验收单所有**；订单行只留生成时冻结的应送分配台账。

## 二、已确认决策（浓缩版，全部 2026-08-28 定稿）

| # | 决策 |
|---|---|
| 三层模型 | `t_delivery_batch`(客户+日期唯一) → `t_delivery_order`(客户签收单，scope 由客户策略决定) → 打印层；内部总表不落物理明细，由台账聚合 |
| 组单策略 | 客户级配置 `doc_scope_type`：CUSTOMER_DATE(跨点总单,delivery_point_id=NULL) / DELIVERY_POINT_DATE(每点一张)；只按客户配置，生成瞬间快照进批次与单据 |
| 聚合规则 | merge_same_item=true 时按五元组合并：`sku+品名快照+单位+规格+单价`；**不同价必拆行**（D-024）；merge=false 一订单行一行 |
| 来源台账 | `t_delivery_source_item`：订单行→送货行分配，生成时冻结，含唯一键(近期一订单行只送一次)；仅 4 个结构性用途：状态回写/幂等/作废释放/撤回判断。**无实收数据** |
| 验收 | 独立验收单为唯一实收录入点（C1 定稿）；明细按**配送点×商品**展开（A类总单）、文员直接在各点行填实收（录入即归属）；**订单行级不做实收派生**（基线 D-026"到订单行"作废）；双向差异均必填原因（1短收/2超收两套字典） |
| 结算 | 依据=验收单 total_amount；`t_sale_order_detail.actual_*` 降级只读镜像列（验收提交时同步），禁止业务直写 |
| 回写 | 送达/验收/撤回全部按 `source_item` 的 DISTINCT sale_order_id 回写，废除 `updateStatusByDeliveryGroup` 按客户+日期推断 |
| 撤回/改单 | 撤回判断=EXISTS 有效 source_item 分配（作废即解锁）；订单编辑护栏：DELIVERED/ACCEPTED 拒改、CONFIRMED+已分配拒改、SETTLED 拒改 |
| 作废/补单 | 送货单 PENDING/PRINTED 可作废(原因必填,新号)；未打印补单=作废重建(整客户覆盖,D-022)；已打印补单=补充单 doc_kind=1(D-023)；手工补生成按客户+日期补齐全部遗漏(D-025) |
| 生成入口 | **手工为主**（录单页「本客户订单已录完」按钮 > 订单列表勾选/按客户 > 定时兜底）；定时 23:30(次日)+06:00 兜底双窗口幂等；总表=工人采购配货来源之一 |
| 撤销验收 | 验收页 SUBMITTED→DRAFT，原因必填+完整审计快照；任一来源订单 SETTLED 则拒绝 |
| 退货 | 验收后真实退货走独立退货单 TH（不撤回历史验收）；换货=退货单+新销售订单；数量上限=实收-累计已退，单价锁原验收价；质检结果仅记结论（reusable/damaged），库存流水待库存模块 |
| 退役 | OrderAdjustment 写入口隐藏→接口标废→下版清理；订单页快速验收三接口(`/actual/*`)与实收编辑列下线 |
