# 送货单矩阵总表与批次视图设计

> **状态**：🟢 设计定稿（2026-08-31 两轮确认收口），**P0-A 矩阵总表已落地（2026-09-01，见 §十二）**，承接基线《[销售订单与送货单关系设计](../销售订单与送货单关系设计.md)》D-001~D-037、《[送货单客户维度设计](送货单客户维度设计.md)》D-038~D-042，新增决策 **D-043 ~ D-054**。
>
> **一句话主张**：送货单据的管理单元是**客户 + 配送日期（批次）**，不是配送点单；A 类跨点合并的纸面形态是**矩阵总表**（行=菜品、列=配送点、格=数量），B/C 类是**每点一张针式点单**。当前代码只有中间那层（`t_delivery_order`）真的活着，上面（批次视图）和下面（打印形态/打印包）都停在文档与未写入的表字段里，所以一遇到跨点合并和批量打印就变形。

---

## 一、本轮确认的业务实况（2026-08-31）

| # | 实况 | 对设计的约束 |
|---|---|---|
| 1 | **跨点合单不用针式**，针式只用于单点配送的单据 | 蓝图 line 64「跨点合单只允许 A4」**维持不变**；矩阵总表走 A4 激光 |
| 2 | **矩阵仍是一菜一行**，但"同一菜"= 菜品 + 单位 + 单价 都相同 | D-024「不同价必拆行」**继续适用于矩阵行**，不因形态改变而放宽 |
| 3 | **矩阵总表不带菜价**，主要给内部人确认，客户也只看一下数量 | 矩阵纸面不出金额；结算依据仍是验收单（关系设计 §2 金额口径不变） |
| 4 | 单点客户「有多少个点就有多少张单」 | B/C 类批次内 N 张单，痛点=逐张点打印/逐张预览/逐张确认 |
| 5 | 当天没有订单的配送点，**列必须存在且为空** | 列集合不能从当天数据 distinct，必须来自主数据快照 |
| 6 | 矩阵**不打单价列**，同名多行改用**价档标记**区分 | 取消"内部版单价列 / 客户版隐藏"双模板设想，矩阵只出一版模板（D-046/D-053） |
| 7 | 单客户最多 **5~6 个配送点** | A4 纵向一页放得下，`colsPerPage` 默认 6，列分页仅作 >6 点兜底（D-045） |
| 8 | 停用点**不进列**，但当天有单则**临时补列** | 快照只含 `valid=1`；ad-hoc 列追加末尾并告警，绝不静默丢量（D-053） |
| 9 | A 类**不需要**同时出每点点单 | 一个批次只一种形态（总单已含全部点数量），`scope_type` 不扩展双出（D-054） |

## 二、两种输出形态对照

| 维度 | A 类：矩阵总表 | B/C 类：针式点单 |
|---|---|---|
| 组单策略 | `CUSTOMER_DATE`，批次内 1 张单（`delivery_point_id=NULL`） | `DELIVERY_POINT_DATE`，批次内 N 张单（每点一张） |
| 纸面 | 行=菜品，列=配送点，格=数量，行尾=合计数量 | 一维明细列表（品名/规格/单位/数量/单价/金额） |
| 是否带价 | **不打单价、不打金额**；同名多行在<b>备注列</b>标 `挡①` 区分（D-046/D-053，品名本身保持干净） | 带单价与金额（蓝图 line 66） |
| 介质 | A4 激光**纵向**（≤6 点一页放得下；>6 点走横向或列分页兜底） | 三联预印连续纸 241×140，固定每页 10 条（蓝图 line 65） |
| 分页 | 纵向行分页 × **横向列分页**（列块），页码 `第 i/j 页 · 列块 k/m` | 纵向分页，跨页重复客户/点/日期/表头 |
| 打印动作 | 单张：强制预览 → 确认 → 回执 | **打印包**：一次汇总预览 → 一次确认 → 队列连续输出 N 张 |
| 空点列 | 必须存在（主数据快照） | 不适用（无单就不出该点的单） |
| 签收 | 总部签收一次 | 各点分别签收 |

> 三者分别建模的原则不变（关系设计 line 534）：**外部单据组单**（scope_type）／**打印形态**（矩阵/点单）／**页面布局**（分页、列块、联数）互不越界。矩阵只是 A 类总单的渲染形态，**不新增单据对象**，单号/状态机/验收/对账仍挂在那张 `t_delivery_order` 上。

## 三、矩阵总表的数据模型（关键：不用改业务表）

```text
行  = t_delivery_order_detail（A类总单的合并明细行，已按 D-024 五元组合并）
列  = t_delivery_batch.layout_json.columns（生成瞬间的客户启用点快照，含空列）
格  = Σ t_delivery_source_item.allocated_quantity
      GROUP BY (delivery_detail_id, customer_dept_id)
```

**为什么行直接取明细行、不重新聚合**：`t_delivery_source_item.delivery_detail_id` 与 `customer_dept_id` 都是 `NOT NULL`（`init_all.sql:3919/3922`），分配量本来就是构成 `detail.num` 的东西，所以取明细行做行键天然满足：

```
恒等式：detail.num == Σ 该行各列格值
```

打印前跑一遍校验，不一致即拒绝出纸并提示到「来源」页排查（W0-2.1 撤回级联的扣除重算也维持这个不变式）。

**现有 `batchView` 不能直接复用**（三处硬伤）：

| 位置 | 问题 |
|---|---|
| `DeliveryBatchMapper.xml:125-140` | 列从 `source_item` distinct 出来 → **当天无订单的点根本不出现**，违背实况 5 |
| `DeliveryBatchServiceImpl.java:43` | 行键只按 `sku_id`（SQL group by 也只到 `sku_id, productName, dept_id`）→ 不同规格/单位/单价被错误并成一行，**破坏恒等式**，也违背实况 2 |
| `views/order/batch/view.vue` | 渲染成"展开行 + tag 列表"，不是矩阵 |

> ⚠️ `DeliverySourceItem` 没有 `spec/unit` 列——**不要为此加字段**，行身份一律走 `delivery_detail_id` 关联送货明细取规格/单位/单价（与 T5 验收点级展开同一口径）。

**历史单回退**（无 source_item 台账）：无法透视出点级格值 → 各点列打 `—`、数量只落"合计"列，页顶提示「历史单无点级分配台账」。

## 四、列快照与空列规则（D-045）

`t_delivery_batch.layout_json`（注释已写"布局参数快照 column_count/rows_per_column"，**建好至今从未被写入**）启用为矩阵布局权威源：

```json
{
  "printForm": "MATRIX",
  "colsPerPage": 6,
  "rowsPerPage": 0,
  "layoutVersion": 1,
  "snapshotAt": "2026-08-31T23:30:05",
  "columns": [
    { "deptId": 12, "code": "D01", "name": "人民路店" },
    { "deptId": 13, "code": "D02", "name": "公园路店" }
  ],
  "priceTiers": [
    { "groupKey": "sku:88|500g/份", "productName": "土豆", "spec": "500g/份",
      "tiers": [ { "rank": 1, "price": 3.20 }, { "rank": 2, "price": 3.80 } ] }
  ]
}
```

规则：

1. **取列**：生成瞬间 `t_customer_dept where customer_id=? and valid=1 and is_deleted=0 order by code, id`；**停用点不进列**；当日无单的启用点**照样进列**（空列）。
2. **临时补列**：若 `source_item` 出现快照外的点（点已停用但当天确有订单），**追加到列末尾**、`adHoc:true` 标记、预览页与纸面列头提示「该点已停用，当日有单临时补列」，绝不静默丢量（D-053）。
3. **只用快照**：打印数据集与页面矩阵一律读快照，不读实时主数据 → 点改名/停用后历史总表重打版式不变（对齐 D-016 快照精神）。
4. **补单/作废重建**：重算列集合，`layoutVersion+1` 并记变更说明；`priceTiers` **append-only**，已有档号永不重排（见 §五）。
5. **补充单**（`doc_kind=1`）沿用**原总单的列快照与列顺序**，页码续打（`第2张·补充`），否则客户手上两份纸对不齐。
6. **列数默认**：`colsPerPage=6`（实况 7：最多 5~6 点 → A4 纵向一页放得下，列分页为兜底而非默认路径）。

**列分页容量参考**（A4 可用宽：纵向 190mm / 横向 277mm；品名 45 + 规格 20 + 单位 12 + 合计 18 ≈ 95mm，每个点列约 16mm）：纵向约 **6 列/页**，横向约 **11 列/页**。

## 五、"不打价"与"不同价拆行"的衔接：价档标记（D-046/D-053）

行按 品名+规格+单位+单价 拆（D-024），纸面一律不打单价与金额 → 同一「品名+规格+单位」可能出现多行且看起来完全相同（例：两行「土豆 500g/份」，数量各 5）。处理：**在备注列标价档标记，品名本身保持干净，不出任何数字价格**。

| 项 | 规则 |
|---|---|
| 档位划分 | 批次内同一「品名+规格+单位」下的不同单价，按**单价升序**排 rank=1,2,3… |
| 标记文案 | 备注列显示 `档① / 档②`（品名本身干净）；rank≥4 用 `档4` 阿拉伯数字，避免圈码字库缺失 |
| 显示条件 | 该「品名+规格+单位」在**批次内**（原单 + 全部补充单）档位数 >1 才显示；单档不打标记，纸面保持干净 |
| 稳定性 | 档号是**批次级快照**（`layout_json.priceTiers`），**append-only**：补单/重建只追加新档，已有档号绝不重排 → 已打印纸面的标记永不改变（对齐"已打印单据不可变"） |
| 跨单一致 | 同一批次内所有单（原单 + 补充单）共用一份 `priceTiers` 渲染，客户手上两份纸的档号互相对得上 |
| 模板 | 矩阵**只出一版模板**（内部确认与客户查看共用，都不带价）；取消上一版设想的"内部版单价列 / 客户版隐藏"双模板 |

金额追溯路径不变：明细行本身有 `price/amount`，看送货单「明细」弹窗、「来源」弹窗与验收单/月结，不依赖矩阵纸面。

## 六、打印形态与模板绑定（D-048）

现状是**隐性失效**：`PrintTemplateMapper.xml:55-66` 的三级绑定 `bind_type=1 and delivery_point_id = #{deliveryPointId}`，A 类总单传 NULL → SQL 里 `= NULL` 恒不成立 → 悄悄回落到客户级/全局默认模板。从 B 类改 A 类的客户（只配过"客户+点"模板）会**直接打错纸且无任何提示**。

改造：

```text
t_print_template 新增：
  bind_scope   varchar(32)  ANY | CUSTOMER_DATE_TOTAL | DELIVERY_POINT
  print_form   varchar(16)  MATRIX | FLAT
```

解析顺序（显式化，总单永不参与点级匹配）：

```text
点单：客户+配送点 → 客户+DELIVERY_POINT → 客户+ANY → 客户 → 全局默认
总单：客户+CUSTOMER_DATE_TOTAL(+print_form=MATRIX) → 客户+ANY → 客户 → 全局默认
```

- 命中"全局默认"时在打印对话框显式提示 `⚠️ 该客户未配总表模板，本次使用全局默认版式`。
- 候选模板列表改由后端出：`GET /order/delivery/{id}/print-candidates`，删除 `views/order/delivery/index.vue:603-606` 前端复刻的三级绑定过滤（`null` vs `undefined` 比较不一致，且规则双写必然漂移）。
- 打印模板管理页绑定树在客户节点下增加两个特殊子节点：`总表(跨点矩阵)` / `各配送点`。

> **实现说明（2026-09-01 P1 落地，见 §十六）**：实际落地用**单一维度 `print_form`（MATRIX/FLAT）**替代「bind_scope + print_form」双维度——印刷形态本身已能区分总单/点单，不必再引入 bind_scope。
> 解析顺序：
>
> ```text
> 点单(FLAT)  ：客户+配送点 → 客户 → 全局默认（限 print_form=FLAT 或空）
> 总单(MATRIX)：客户 → 全局默认（限 print_form=MATRIX；delivery_point_id=NULL 时"客户+配送点"级天然不命中）
> ```

## 七、打印包：B 类 N 张点单一次输出（D-050）

`t_print_task`（`init_all.sql:1293`）字段是 hiprint 试验件（`order_id/template_content JSON`），**全工程零 Java 引用**，重建为送货单打印任务：

```text
t_print_package: id, batch_id, package_no, media_type, status, preview_time,
                 total_count, success_count, fail_count, create_by/time, remark
t_print_task:    id, package_id, delivery_order_id, seq_no, template_id, copies,
                 device_key, status(0待打/1已预览/2打印中/3成功/4失败/5取消/6跳过),
                 attempt_no, retry_of_task_id, receipt_time, error_msg, ticket_id
```

流程（对齐蓝图 line 128/131/133）：

```text
批次行〔打印包〕→ 列出包内 N 张（单号/点/解析模板/份数/设备/状态）
  → 逐张可改模板与份数（仅本次生效，显式「设为默认」才写绑定）
  → 〔汇总预览〕一次打开（不逐单弹预览）
  → 〔开始打印〕按 seq_no 队列执行，任一失败立即停止并保留未执行清单
  → 逐张回执：成功才 print_count+1 / 状态推进 PRINTED；失败不计数，可重试（新任务 retry_of 关联）
```

**连续输出的技术路线**：JimuReport 一张报表只吃一个参数值，因此新增包级数据集，而不是前端逐个 `window.open`：

```text
GET /print/deliveryPackageData?packageId=&ticket=
→ rows[{orderCode, deliveryPointName, deliveryDate, seqNo, productName, spec, unit,
        num, price, amount, pageBreakFlag}]
模板按 orderCode 分组 + 「每组起新页」→ 一次预览、一次打印、连续输出 N 张
```

票据需支持包级绑定：`issuePrintTicket({packageId})`（现 `PrintTicketService` 只绑 `deliveryOrderId`）。A4 浏览器链路可先用"逐单签发票据 + 前端队列"过渡，针式本地助手（W0-4.2/4.3，硬件阻塞）到位后统一走包级数据集。

## 八、送货单据页：批次为主、单据为从（D-043）

```text
送货单据页（主行 = 客户 + 配送日期 = 批次）
┌ 客户A  12-05  跨点总单·矩阵   1张 待打印1  合计 320件   [总表预览][打印][结构][补单]
┌ 客户B  12-05  每点一单·针式   3张 已打印2/3            [打印包:剩1张][总表][补单]
│  ├ HS-B001  点1  已打印×1   [明细][来源][打印][送达][作废]
│  ├ HS-B002  点2  已打印×1
│  └ HS-B003  点3  待打印
└ 客户C  12-05  🔴待验收 2 张（提醒聚合到批次主行）
```

- 后端新增 `GET /order/delivery/batch-page`：按 `customer_id, delivery_date` 分组分页，聚合 `scopeType / docCount / printedCount / pendingCount / deliveredCount / totalQuantity / totalAmount / maxReminderLevel / printForm`。**必须后端分组**——前端分组会被分页切断同一批次。
- 筛选补齐：客户多选、配送点多选（仅对点单生效）、单据形态（总单/点单/补充单）、打印包状态。现在 `index.vue` 的 `queryParams` 只有 `code/status/scopeType/deliveryDate`，**连客户筛选都没有**（后端 `selectDeliveryOrderList` 早就支持 `customerId/deliveryPointId`，前端没暴露）。
- W0-3.2 待验收提醒由单行标色改为**批次主行聚合**（红>黄>无），否则 5 张点单里 1 张红在批次视图里被淹没。
- 生成入口维持 D-039 三步式（`group-preview` 客户维度清单 → 确认），不动。

## 十八、D-055 送货单视图化（2026-09-03 业务定稿 + 落地）

> **状态**：🟢 已落地（大重构）。**核心主张**：送货单不是独立单证，而是**订单的视图**——文员下好单数据即存在（客户日总表实时体现），无需生成/定时/补单。本设计文档 §一~§十七 的「A 类总单单证层」概念自此**作废**，保留矩阵/点单两种**打印形态**与「备注列档位」等视图层设计。

### 为什么视图化（业务账）

- 订单明细自带 `customer_dept_id`（配送点）+ `product_price`（价格快照）+ `num`（应送）→ **生成配送点送货单的全部数据从订单就能算出来**
- 应送=订单数、实收=现场录入、差异=实收−应送——**无中间态**（旧模型「送货数<订单数」的 source_item 台账不再需要）
- 临时加送=新建订单（同客户+日期）→ 日总表/点单实时刷新，验收自然包含
- 验收=结算依据，创建时快照应送行，提交后订单数据不变

### 业务规则书（配送前后）

| 阶段 | 规则 |
|---|---|
| 配送前（未打印） | 改动=正常更新订单，无标记（change_type=0） |
| 配送后（已打印） | 原订单数据不变，变更以标记附加订单明细：加单(新行 change_type=1, 应收+实收)/换货(被换行标3+换入行标2 同 change_group)/退货(原行标3, 应送实收归0) |
| 例外 | 实收>应收（现场多加）→ 正常，不标记，验收直接录实收 |
| 打印分界 | "已打印" = 该 客户+日期+点 在 `t_delivery_print_log` 有记录 |

### 落地内容

**删除**（过度设计清理）：生成服务/补单/作废重建/三态分支/定时任务、4 个生成接口、3 个生成专用查询、打印包全套（P2）、打印拆分配置（W0-2.2）、打印资源登记（W0-6）——**后端测试 286→239**。

**数据模型**：
```text
t_sale_order_detail + change_type/change_group/change_remark   -- 变更标记
t_delivery_print_log                                           -- 打印分界（客户+日期+点）
acceptance.delivery_order_id → 可空（历史兼容）；+ delivery_date（验收=客户+日期+点）
acceptance_item + sale_order_detail_id                          -- 应送行=订单明细
```

**核心服务**：`DeliveryChangeService`（加单/换货/退货标记写入，仅已确认订单）；`AcceptanceService#createByCustomerPoint`（应送行=订单明细含标记，一维一验）；`DeliveryBatchService#selectPointView`（点单视图）；`WorkbenchMapper.selectPendingAcceptance` 重写（订单维度）。

**前端**：客户日总表页=唯一入口（矩阵/配货/点单三口径）；点单区（配送点下拉+明细+标记tag+打印/验收）；订单列表「配送后变更」按钮+抽屉；送货单据菜单下线（s21）；工作台待验收按订单维度。

**验证**：239/239 全绿；真机链路（点单含标记/验收76.72/退货加单标记/工作台订单维度/矩阵无父级列/点单下拉按客户）全通过；修复 4 个真机 bug（验收金额漏算/实收取0镜像默认/加单order_code/acceptance字段名）。

## 十九、D-055 收尾：三口径同源与打印接通（2026-09-04 落地）

> **状态**：🟢 已落地。**核心主张**：D-055 把送货单改成订单的视图，但矩阵/配货两口径与打印仍绑在

> **三口径统一到同一数据源（订单明细）**，并把打印主体从「单据」改为「客户+日期(+点)」。

### 十九.1 三口径同源（矩阵 / 配货 / 点单）

| 口径 | 主口径数据源（D-055 后） | 历史回退（D-055 前只读） |
|---|---|---|
| 矩阵总表 | `selectMatrixDetailsFromOrder` + `selectMatrixCellsFromOrder`：行=订单明细按**五元组**合并（D-024 不同价必拆行）、格=(五元组×配送点) `SUM(num)` | 订单明细无数据 → `selectMatrixDetails`/`selectMatrixCells`（送货明细行 + source_item 台账，行身份=detailId） |
| 配货总表 | `selectBatchViewRowsFromOrder`：标准品名×配送点，不拆价不显价（D-027/28） | `selectBatchViewRowsBySource` → `...ByDetail` |
| 点单 | `selectValidByCustomerPointDateForView`（客户+日期+点 订单明细行含标记） | 同左（本就订单口径） |

- **读口径统一** `o.status >= 1`（非草稿即应送）：退货行 `num` 已归 0 自然不计，全组为 0 的纯退货行不进矩阵；
  验收后回看本天不再空表。**写口径不变**：验收创建仍只取 `status = 1`（与一维一验守卫配套）。
- **行身份键**：主口径 = `groupKey(sku,品名快照,规格,单位) + "|" + priceKey(单价)`；历史口径 = `"d:" + detailId`。
  故 `CellRow` 增列 skuId/productName/spec/unit/price 与行侧对位（两侧 SQL 回传同一组字段）。
- `historyFallback` 语义修正：**走历史口径且无点级台账**才为 true（旧实现 `cellIndex.isEmpty()` 在订单口径下永不触发）。
- **布局定格退役**：`refreshLayout`（原由生成服务在出单成功后调用）随生成服务一并删除；
  `layout_json` 只读历史批次快照，无快照按启用点实时推导（`layoutDerived=true`）。
