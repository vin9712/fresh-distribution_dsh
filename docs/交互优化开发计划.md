## Phase 0：用报价demo.csv 初始化商品库与商品信息（本轮执行）

### 目标

将 `docs/报价demo.csv`（88 条商品，7 个商品类型）灌入开发库：

1. **商品分类**：补齐 CSV 中用到的分类（幂等，不破坏现有分类树）
2. **商品库 SPU**：以 CSV **品名**（剥离括号/斜杠规格信息后的基础名称）建 SPU（`t_product_spu`）
3. **商品信息 SKU**：每行 CSV 建 1 个标准 SKU（`t_product_sku`，客户无关）：
   `name` = 品名，**括号/斜杠内的规格信息 → `spec_name`**（如 `新鲜土豆(大)` → name=新鲜土豆 / spec_name=大），
   `sale_price` = 本期执行价
4. **报价单**：为演示客户「丽宫」(id=10) 生成一张**已发布**报价单（88 条明细，本期执行价，
   `product_name`=品名、`product_spec`=规格快照），使录单取价（配送点覆盖 > 客户报价 > 模板）立即可用
5. **编号序列衔接**：`biz_code_seq.sku_code` 与 `skuQuote:{当日}` 调整，避免与系统自动生成冲突

### 品名 / 规格拆分规则（Q3 已确认）

- 正则剥离行尾的 `(...)`、`（...）`、`/...` 后缀作为 `spec_name`，剩余为基础品名
- 涉及行（已核实）：`新鲜土豆(大)`、`新鲜土豆/100g以上`、`青尖椒(大)`、`青尖椒(中)`、`铁棍山药（蔬菜）`
  - 例：`新鲜土豆(大)` → SPU「新鲜土豆」+ SKU(name=新鲜土豆, spec_name=大)
  - 例：`新鲜土豆/100g以上` → SKU(name=新鲜土豆, spec_name=100g以上)（同品名不同规格，SKU 唯一键 `(category_id,name,spec_name,unit)` 天然区分）
- 无后缀行：`spec_name` 留空
- 助记码基于**品名**生成（与后端 `PinYinConvertUtils` 规则一致）

### CSV 数据事实（已核实）

- 88 条数据行，无重复名称、无重复（类型,名称,单位）组合
- 编码 UTF-8 with BOM、CRLF 换行、部分价格带尾随空格（如 `3.50 `，需 trim）
- 分类分布：叶菜类 19 / 根茎类 31 / 瓜类 10 / 菌菇类 8 / 葱蒜类 6 / 半成品类 7 / 佐料类 7
- 单位：87 条「斤」、1 条「袋」（娃娃菜）

### 实现方式

**生成器 + SQL 存档 + 验证脚本**（复用现有 `.dsh-e2e/` 工具链）：

1. 新增 `.dsh-e2e/gen-product-init.js`（Node）：
   - 读 `docs/报价demo.csv`（utf-8-sig 去 BOM，trim 价格）
   - 用 `pinyin-pro`（复用 `RuoYi-Vue3/node_modules/pinyin-pro`）预计算每行助记码
     （与后端 `PinYinConvertUtils.toFirstChar` 同规则：名称拼音首字母大写）
   - 生成 `sql/s7_product_init.sql`（幂等写法，见下）
2. 新增 `sql/s7_product_init.sql`（生成产物，提交存档）：
   - 分类：`INSERT ... ON DUPLICATE KEY UPDATE`（name 全局唯一，天然幂等）
   - SPU：唯一键 `(category_id, name)` → `INSERT IGNORE` + `SELECT` 回填 id；
     name = 品名（剥离规格后缀）；多条 SKU 对应同一品名时仅建 1 条 SPU
   - SKU：唯一键 `(category_id, name, spec_name, unit)` → `INSERT IGNORE`；
     name = 品名、spec_name = 规格后缀（无则空）；
     `code` 显式 `S00000001`~`S00000088`（不与现有 S00000001/2 冲突，当前库仅 2 个 SKU）
   - 报价单头+明细：按 code `BJ{yyyymmdd}xxxxx` 先查重，存在则跳过（幂等）；
     状态 status=1 发布、valid=1、生效今天 ~ +30 天；
     明细 `product_name`=品名、`product_spec`=规格、`price`=本期执行价
   - 序列衔接：`UPDATE biz_code_seq SET seq=88 WHERE biz_key='sku_code'`（当前 seq=2）；
     `skuQuote:{当日}` 设为当日已生成报价单数（防重号）
3. 用 `.dsh-e2e/apply-sql.js sql/s7_product_init.sql` 应用
4. 新增 `.dsh-e2e/verify-product-init.js`（Node + mysql2，仿 `verify-s0-*.js`）：
   - SKU 总数 = 88（新增）+ 2（原有）= 90；SPU 总数 = 88
   - 抽检：大白菜/娃娃菜(袋)/新鲜土豆(大) 的 category/unit/sale_price/mnemonic
   - 报价单 1 张、明细 88 条、价格=本期执行价、status=1、valid=1
   - 幂等：脚本重跑一次，数量不翻倍

### 过程中发现并修复的 Bug（取价引擎）

- **现象**：`/price/query?customerId=10&skuId=3` 返回 `price:null`，已发布报价不生效
- **根因**：`ProductSkuQuoteDetailMapper.xml` 的 `selectActivePriceByCustomerAndSku` 条件为 `sq.valid = 0`
  （2026-08-17 commit 3e1db22 引入），与 `selectCustomerActiveQuote`（valid=1 & status=1）及

- **修复**：`sq.valid = 0` → `sq.valid = 1`（仅此一处误用，已全仓排查）
- **验证**：`mvn -pl lin-distribution clean install -o -DskipTests` + 44 单测全绿；重启后
  `/price/query` 命中：大白菜 1.20 / 娃娃菜 2.40 / 新鲜土豆(大) 1.60，均 source=2
- **回归守护**：verify-product-init.js 增加「取价 SQL 使用 valid=1」与「取价等价 SQL 断言」两项检查

## Phase 4：报价详情页 Excel 式批量调价（方案 §3.3，P3）

文件：`RuoYi-Vue3/src/views/product/quote/detail.vue`

1. **键盘流**：`keyboard-config` 定制——Enter 仅在「新报价」列向下移动，其余列 Tab 移动
   （vxe `edit-config` + `activated`/`keydown` 事件处理）
2. **批量填充**：右键菜单「向下填充 / 向上填充」（`menu-config` v4 结构 `{ body: { options: [[...]] } }`，图标用 `vxe-icon-custom-column`）；顶部工具栏「批量调价」按钮：输入涨幅%（如 5），对选中行统一计算新报价
3. **固定列**：商品名称列 `fixed: 'left'`、操作列 `fixed: 'right'`
4. **异常预警**：新报价偏离上次价/成本价 >30% 或 < -10% → 单元格橙色背景/边框（`cell-class-name`），提示「涨幅异常」

## 通用技术要点（执行各阶段时注意）

- vxe-table v4 `menu-config` 结构为 `{ body: { options: [[...]] } }`，非 v3 直数组
- 右键菜单图标：`vxe-icon-wipe` 不存在，用 `vxe-icon-custom-column`
- 树形表格不支持 `checkbox-config.range`（QuickTable 已自动降级）
- 列设置持久化需 grid 唯一 `id` + 每列 `field`
- 全局快捷键需过滤 `compositionstart/end`（中文输入法）
- 大数据表格开启虚拟滚动（`scroll-y.gt=100`）
- 后端改动后启动前必须 `mvn -pl lin-distribution clean install -o -DskipTests`（否则旧 XML 残留）
