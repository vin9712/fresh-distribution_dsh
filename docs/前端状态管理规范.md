# 前端状态管理规范（W0-5.5）

> 依据：`客户端化ERP优化蓝图.md` §2（共享设备/布局持久化/草稿冲突决策）、§4.2（"Pinia 虽已安装，但当前项目已有既有状态管理方式。实施新能力前需统一状态边界，避免同一业务同时使用多套全局状态方案"）。
> 状态：✔ 已定稿（2026-09）。本规范为后续所有前端页面/组件的**准入检查**依据；既有代码按"收敛项"逐步对齐，不做大爆炸式重写。

---

## 1. 状态分类与归属决策表

任何一份状态先回答两个问题：**谁需要它？刷新后还要吗？** 然后按下表归属，禁止跨层混用：

| 类别 | 特征 | 归属 | 现状示例 |
|---|---|---|---|
| A. 会话/框架态 | 登录态、路由权限、标签页、字典缓存、锁屏、主题 | **Pinia store**（`src/store/modules/`） | user / permission / tagsView / dict / app / settings / lock |
| B. 服务端数据 | 列表、明细、表单草稿（后端双写）、单据状态 | **组件 `data()` + API 调用**，不进 Pinia | 各业务页 `templateList`、`queryParams` |
| C. 用户偏好（跨会话） | 分屏占比、列设置、列宽、面板宽度、本机草稿 | **localStorage**，键必须带**用户命名空间** | SplitWorkspace `splitws:u{userId}:*`、saleDraft `saleDraft:u{userId}:*` |
| D. 页面瞬时态 | 对话框开关、loading、选中行、步骤状态 | **组件 `data()`**，父子用 props/emit | `printOpen`、`voidSubmitting` |

判定口诀：

1. **跨页面共享 + 登录相关** → Pinia；**单页面独立** → 组件 data；**跨会话本机记忆** → localStorage；**父子传递** → props/emit。
2. 同一份数据**只允许一个归属**：例如分屏占比若进了 Pinia 就不要再写 localStorage（反之亦然），避免双写漂移。
3. 判断不了时默认**组件 data（D 类）**——提升为全局状态需要给出理由并在本文档 §5 登记。

## 2. Pinia 使用细则

1. **框架层 store 保持现状**（user/permission/tagsView/dict/app/settings/lock），新页面不得往这些 store 里塞业务字段。
2. 新增 store 仅当满足：≥2 个互不相关的页面/组件共享同一份可变状态，且属于 A 类。业务数据（B 类）即使"多个对话框共用"也优先 props/emit 或路由参数，不建 store。
3. store 内不做 API 调用以外的副作用（不改 localStorage、不注册 window 事件）；字典缓存类"读接口+缓存"是既有例外，保持。
4. 组件中使用 `useXxxStore()`，响应式解构用 `storeToRefs`；禁止 `mapState/mapGetters`（Options API 遗留用法不再新增）。
5. store 的 state 必须可序列化——不放 DOM 引用、定时器句柄。

## 3. localStorage 使用细则（C 类）

### 3.1 键命名（强制）

```
<域前缀>:u{userId}:{业务键}
```

- `域前缀`：功能域小写短横线名，如 `splitws`（分屏）、`saleDraft`（销售草稿）、`qtcols`（表格列设置）。
- `u{userId}`：**必须**取当前登录用户 ID（`useUserStore().id`），共享 PC 互不串号（蓝图 §2 共享设备决策）。
- 同一 PC 未登录即可用的场景（如锁屏前的设置页）才允许省略用户段，需在键旁注释说明。

### 3.2 值结构（强制）

- 值带**版本号与必要元数据**：`{"v":1, ...负载}`；结构升级时旧值按 `v` 不匹配即丢弃（对齐 W0-5.3/W0-5.1 既有做法）。
- 单键体积目标 < 64KB，硬上限 256KB（对齐草稿工具口径）；超限应裁剪负载而不是放宽上限。
- 写入前 try/catch（隐私模式配额溢出不抛错到用户界面）。

### 3.3 读写收敛

- 新代码统一走 `src/plugins/cache.js`（`cache.local.getJSON/setJSON`）或组件内封装，不再散落裸 `localStorage.setItem` 字符串拼接。
- 键名常量集中定义在使用组件/工具的顶部并导出，禁止在多处手拼同一键名。

## 4. 其他机制边界

| 机制 | 允许范围 | 禁止 |
|---|---|---|
| props / emit | 父子组件唯一通信方式 | 兄弟组件借父组件转发深层状态（超过 2 层改用组合式函数或 provide） |
| provide / inject | 仅框架层（layout 与其内部组件），如 TagsView/ScrollPane | 业务页面间用 inject 传业务数据 |
| window 事件监听 | 键盘类统一走 `src/utils/shortcut.js`（W0-5.2），resize 等组件级监听须在 onBeforeUnmount 清理 | 业务页自建 keydown 监听、全局 window 挂载变量 |
| eventBus / mitt | **不引入**（现无任何使用，保持为零） | 任何全局事件总线 |
| sessionStorage | 仅 `plugins/cache.js` 封装（会话级临时缓存） | 存放跨会话偏好（刷新后应保留的数据用 localStorage 或后端） |
| 路由参数/query | 跨页跳转携带的单次上下文（如订单 ID） | 大对象序列化塞 query |

## 5. 现状盘点与收敛项

### 5.1 已符合规范

| 资产 | 类别 | 说明 |
|---|---|---|
| `store/modules/*` 7 个 store | A | RuoYi 框架层，保持 |
| `SplitWorkspace`（W0-5.1） | C | `splitws:u{userId}:{key}`，值带版本，恢复默认清存储 |
| `saleDraft.js`（W0-5.3） | C | 用户命名空间 + ver/rev 版本 + 容量 20 条/256KB + 7 天过期 + 恢复校验 |
| `utils/shortcut.js`（W0-5.2） | 事件 | 全局唯一 keydown 监听、作用域优先级、IME 保护 |
| 各业务页列表/对话框状态 | B/D | 组件 data + API，符合 |

### 5.2 收敛项（不阻塞新页面，随触碰即改）

| 资产 | 偏差 | 收敛动作 |
|---|---|---|
| `TreePanel` 面板宽度 | `props.storageKey` 无用户命名空间、无版本号 | 迁移到 SplitWorkspace（W0-5.1 备注既定方向）或补 `:u{userId}:` 段 |
| `RightToolbar` 列显隐记忆 | storageKey 无用户命名空间 | 键格式补用户段，旧值容忍丢失（列显隐重建成本低） |
| `QuickTable` 列设置 | storageKey 无用户命名空间 | 同上；S1/S3 新接入页面一律用新键格式 |
| `views/demo/*` 演示页 | 演示键未带真实 userId 语义 | 演示页仅用 `u1` 固定段，不进生产菜单，无需处理 |

> 收敛项统一口径：**共享 PC 串号仅影响个人偏好显示，不涉及数据安全**（业务草稿已由 W0-5.3 治理），故按"触碰即改"推进，不专项排期。

## 6. 反模式清单（code review 一票否决）

1. 业务组件里 `defineStore` 新建 store 存放服务端列表数据；
2. localStorage 裸写不带用户命名空间/版本号的键；
3. 同一状态 Pinia 与 localStorage 双写；
4. 组件在 `mounted` 直接 `window.addEventListener('keydown', ...)`（应走 shortcut 服务）；
5. 引入 mitt/eventBus 或往 `Vue.prototype`/`globalProperties` 挂业务状态；
6. 通过修改 RuoYi 框架 store（user/permission 等）携带业务字段；
7. props 传对象后子组件直接改写对象属性（应 emit 回父组件）。

## 7. 新页面/组件接入准入检查

提交前端页面/组件前自查（对齐《快捷键规范与冲突表.md》的准入检查模式）：

- [ ] 每份状态归入 §1 四类之一，且只有一个归属；
- [ ] 未新建 Pinia store（或已给出 §2-2 的理由并登记）；
- [ ] localStorage 键符合 `域:u{userId}:{业务键}`，值带 `v` 版本号，写入有 try/catch；
- [ ] 键盘监听走 shortcut 服务（如在《快捷键规范与冲突表.md》注册表登记键位）；
- [ ] 组件级 window 监听（resize 等）在卸载钩子清理；
- [ ] 草稿/单据类数据走后端双写 + 本地兜底（参照 saleDraft 模式），本地只做断网兜底；
- [ ] 未引入新全局状态库或事件总线。
