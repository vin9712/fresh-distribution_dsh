# 生鲜配送 ERP 前端交互设计指南

> 本文档面向生鲜配送 ERP 的 Web 前端设计，聚焦于**快速录单**场景的高效交互，目标是让 Web 端拥有接近 Windows 客户端的操作效率与直接感。
> 技术栈建议：Vue3 + TypeScript + Vite + Element Plus + vxe-table + Pinia。

---

## 1. 设计目标

- 提升录单效率：减少鼠标点击，强化键盘操作。
- 降低操作路径：减少页面跳转，单页完成核心业务。
- 保障数据录入准确性：实时校验、智能联想、快速定位。
- 适应高频重复操作：常用商品、快捷批量操作、草稿自动保存。
- 保持界面紧凑：高信息密度，减少视觉干扰。

---

## 2. 整体布局设计

### 2.1 布局原则

- **少跳转**：采用多标签页工作台，避免频繁切换页面。
- **高密度**：内边距紧凑，表格占据主要区域，减少卡片嵌套。
- **可折叠**：侧边菜单可折叠为图标，扩大内容区。
- **固定顶栏**：顶栏常驻，放置全局搜索、通知、用户信息。

### 2.2 推荐布局结构

┌──────────────────────────────────────────────────────────────┐
│ 顶栏：Logo | 工作台切换 | 全局搜索 | 通知 | 用户 │

│ 侧边 │ 标签页栏（可滚动、可拖拽、可固定） │
│ 菜单 │───────────────────────────────────────────────────────┤
│ │ 内容区（紧凑表单/表格） │
│ │ │
│ │ │

- 侧边菜单：支持**折叠**，可绑定快捷键呼出。
- 标签页：支持**拖拽排序、右键操作、固定**。
- 内容区：去除多余留白，表格占满可用空间。

## 3. 核心交互模式

### 3.1 键盘快捷键（核心）

在录单等高频页面，键盘操作能极大提升效率。以下为建议快捷键：

| 场景     | 快捷键            | 作用                         |
| -------- | ----------------- | ---------------------------- |
| 录单页面 | `F2`              | 新增订单行                   |
| 录单页面 | `F3`              | 聚焦搜索框                   |
| 录单页面 | `Ctrl + S`        | 保存草稿                     |
| 录单页面 | `Ctrl + Enter`    | 提交订单                     |
| 表格内   | `Enter`           | 确认当前单元格并跳到下一行   |
| 表格内   | `Tab / Shift+Tab` | 横向移动编辑单元格           |
| 表格内   | `Delete`          | 删除选中行                   |
| 全局     | `Ctrl + K`        | 全局搜索（商品、客户、订单） |
| 全局     | `Ctrl + N`        | 新建订单                     |

**实现方式**：使用 `vue-use` 或自定义指令，在页面挂载时监听键盘事件，注意避免与浏览器默认快捷键冲突。

### 3.2 右键菜单

- 表格行右键：复制、粘贴、删除、插入行、设为常用、查看详情。
- 标签页右键：关闭、关闭其他、固定、刷新。
- 输入框右键：粘贴纯文本、清空、历史记录。

**推荐组件**：`@imengyu/vue3-context-menu` 或 `v-contextmenu@next`。

### 3.3 拖拽操作

- 表格行拖拽排序（调整打印顺序、分拣顺序）。
- 标签页拖拽排序。
- 常用商品面板中的商品可拖拽到订单表格。

**推荐组件**：`vuedraggable`（基于 Sortable.js）。

## 4. 表格交互增强（配合 vxe-table）

vxe-table 是表格交互的核心组件，需深度配置以满足桌面级体验。

### 4.1 开启虚拟滚动

```js
:scroll-y="{ enabled: true, gt: 100 }"  // 超过100行启用虚拟滚动

4.2 单元格编辑优化
双击进入编辑，单击选中行。

编辑时自动全选内容。

支持下拉自动完成（如商品名称、单位）。

支持日期、数字等控件。

4.3 批量操作条
选中多行后，表格上方浮现操作条（类似 Excel）：
已选 5 项  [批量改价] [批量改单位] [删除] [复制]

4.4 列设置
支持列显示/隐藏、拖拽调序、固定列。

支持保存个人列配置（后端存储或 localStorage）。

5. 搜索与选择控件
5.1 全局搜索框
类似 Everything 的极速搜索，输入即搜。

支持商品、客户、订单、配送点。

结果分组展示，键盘上下选择，回车直接跳转。

5.2 录单商品搜索
远程搜索 + 防抖，输入后 100ms 内请求。

下拉列表显示：商品名称、别名、客户编码、价格、库存（如果有）。

支持拼音首字母、汉字、编码混合匹配。

选中后自动加入表格，焦点自动跳到数量列。

5.3 常用商品面板
根据当前客户历史订单，展示最常购买的 20 个商品。

点击即可加入订单表格。

面板可折叠、可拖拽商品到表格。

6. 状态保持与草稿恢复
录单页面使用 keep-alive 缓存，切换标签页再回来数据不丢失。

草稿每 30 秒自动保存到后端或 localStorage，刷新后可恢复。

全局状态使用 Pinia，避免组件间通信复杂。

7. 可选技术路线：进一步模拟桌面端
若希望 Web 端拥有几乎等同于 Windows 客户端的体验，可考虑以下方案：

7.1 纯 Web + PWA
使用 PWA 技术，支持离线访问、安装到桌面、全屏模式。

利用 Web Workers 处理大数据量计算，保持 UI 流畅。

使用 IndexedDB 缓存基础数据（商品、客户），减少网络请求，实现秒开。

7.2 壳方案：Electron / Tauri
用 Electron 或 Tauri 将 Web 应用打包成桌面程序，获得原生窗口、系统级快捷键、本地文件访问等能力。

优点：开发仍然是 Web 技术，用户体验接近原生。

缺点：需要处理更新、安装包体积等。

若用户主要在办公室使用，且对性能要求高，Tauri（Rust 后端，体积小）是不错的选择。

8. 实施建议
基于现有 RuoYi-Vue3 二创，不需要完全推翻，而是：

改造路由和标签页：使其更流畅，支持拖拽、右键、固定。

为高频页面（录单、商品管理）定制专属交互：如快捷键、批量操作条。

引入全局快捷键和右键菜单。

使用 vxe-table 替换原有的 el-table，并深度配置单元格编辑、虚拟滚动等功能。

优化搜索控件：增加防抖、远程搜索、拼音匹配。

逐步加入 PWA 或 Tauri 支持，根据用户环境决定。

9. 总结
方面	建议
布局	紧凑、多标签页、可折叠侧栏、减少跳转
交互	大量键盘快捷键、右键菜单、拖拽操作
表格	vxe-table 全功能开启，虚拟滚动、单元格编辑、批量操作条
搜索	全局极速搜索 + 录单商品智能联想 + 常用面板
状态	keep-alive + Pinia + 自动草稿
可选	PWA 或 Tauri 打包
以上设计思想旨在让 Web 端生鲜 ERP 拥有桌面软件的效率和直接感，同时保留 Web 的灵活性和可维护性。
```
